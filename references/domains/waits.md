# 等待事件与耗时分析：状态机、计量口径和阻塞解释

与 [公共深度规则](../common/research-depth.md) 一起使用。一个等待名称至少涉及等待对象、上报状态、真实排队/唤醒机制和统计接口；它们可能并不一一对应。枚举或上报调用只能作为入口。

## 明确研究的是哪种“时间”

先拆开当前等待事件、当前等待开始时间、单次耗时、累计耗时/次数、语句耗时、超时阈值。为每个量记录生产者、时钟、单位、起止点、聚合主体、重置时机和可见接口。不能把累计值当本次耗时，也不能把一个状态名称当作时长。

等待分类须回到实现：锁/LWLock、I/O、网络、条件变量/信号量、线程池调度、WAL/复制、定时 sleep 等。名称相似时核对等待队列和唤醒生产者，不以类别名称推断阻塞者身份。

## 追完整个状态机

| 阶段 | 要读到的关系 | 要记录的反例 |
|---|---|---|
| 前置检查 | 快路径、是否需要等待、队列/锁保护、观测开关 | 无竞争时可能不进入等待 |
| 进入 | 入队顺序、状态/事件写入、开始时间、旧状态保存 | 写了状态但尚未实际 sleep |
| 阻塞 | sleep/latch/semaphore 的条件、循环、信号处理、锁释放 | 虚假唤醒、唤醒后仍需重试 |
| 结束 | 谁满足条件/授予资源、何时出队、状态恢复与结束计时 | 等待结束不代表操作已经完成 |
| 异常 | 取消、超时、死锁、ERROR、线程退出的清理 | 队列与状态清理的执行顺序不同 |
| 采样 | 生产者到快照再到视图/统计字段 | 短等待漏采、读取时已切换状态 |

查上报函数是否返回旧状态、是否支持只读/嵌套、是否受运行参数约束；查正常和 PG_CATCH/清理路径各如何恢复。宏名相同不代表线程、会话、线程池和分布式路径相同。涉及线程池时明确状态归属于 worker、session 还是后台线程，标识如何关联。

对于锁等待，分别追锁拥有者/等待者、队列排序、冲突判定、授予与死锁检测；并发快照可能读不到唯一阻塞者。对于 I/O 或网络等待，核对同步/异步调用、系统调用重试和上报窗口；不要把整个 syscall 耗时都自动归入某个事件。

## 计时公式必须能从代码重建

读获取时钟的具体函数与类型，而非依据变量名猜测。说明是墙钟、单调计时还是平台封装；减法、溢出、精度截断和小于最小单位时的处理都影响结果。未读实现时保留未知，不套用其他版本的时钟性质。

累计表逐项记录：`delta = end - start` 在何处计算，什么条件累计，最小/最大值如何更新，次数在开始还是结束增加，是否按线程/会话/节点/事件聚合，何时重置、如何并发读取。执行计数增加而累计时间为零，可能是单位/采样/开关问题，不能直接认定没有等待。

“等待时间长”需要一个明确参照：单次、区间差分、分位数或阈值。区间差分必须确认两次采样主体、计数周期、是否重启/重置和计数回绕一致。无法确定时不要计算具有诊断含义的速率。

## 观测和实验

如果要给出 SQL，加载 views 手册并追字段生产者、权限、NULL 和快照一致性。当前状态、历史累计和语句日志各能证明不同事情；当前无等待不能否认过去发生等待。

最小实验包括：无竞争对照、构造可控等待、释放资源、取消或超时、结束后再观测。记录两个以上参与者的会话/线程/节点身份、动作时间线、采样间隔和开关。超时实验要先追阈值从何读取、何时开始计时、由谁触发信号；不能把 deadlock timeout、lock timeout、statement timeout 混称一个计时器。

实验未运行则只交付计划。运行后比较源码预期的状态迁移、队列清理和计数变化；一次未采到短事件应记采样不足，不能记该路径不存在。

## 常见竞争解释

- 同一状态持续显示：确实阻塞、嵌套恢复不当、快照/标识复用、退出清理缺失分别需要证据。
- 时间增长但业务无进展：等待本身、反复短等待、工作与等待交替、累计主体不一致需要时间线区分。
- 取消后仍看到记录：区分命令取消、事务清理、后台任务、缓存记录及当前快照。
- 增大超时后错误消失：只能说明观察窗改变，不能证明竞争消除或吞吐改善。

## 交付与充分性

`state_lifecycle` 写实际状态图、队列/资源和正常/异常出口；`timing_and_scope` 写计量公式、开关、主体、重置；`cancellation_and_observation` 写取消清理、字段来源、采样边界和区分实验。

应能解释一个最近替代路径：无竞争、虚假唤醒、取消或统计关闭。未追到唤醒者时不能断言根因；未追到计时终点时不能给出精确耗时公式；未做运行采样时不能保证某视图一定捕获该事件。机制可独立复用，具体阻塞场景由 errors/views/decoding 等领域组合。
