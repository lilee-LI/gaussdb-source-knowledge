# 外围工具：参数到执行阶段、数据语义与失败恢复

与 [公共深度规则](../common/research-depth.md) 一起使用。研究 import/export、dump/restore、loader 等工具时，命令名、源目录名和服务器能力不能互相替代。参数解析只是入口，交付应解释实际产生的 SQL、数据流、提交边界及失败后的状态。

## 绑定工具和环境

核对 Makefile/CMake/安装/包装脚本、实际二进制版本、构建特性、客户端库、源端与目标端产品/版本/模式。目录 `pg_dump` 不证明用户命令一定叫 pg_dump；源码中的 gs_restore 也需确认构建/安装目标。

区分纯客户端参数错误、连接/认证错误、服务端 SQL 错误、文件/格式错误、worker/网络错误和外层脚本退出。保留原始退出码、stderr、服务端日志和阶段标识，不能只据屏幕文本归因数据库。

## 参数不是独立开关列表

为每个相关选项记录：短/长名、默认、取值解析、重复/覆盖顺序、互斥/依赖、环境变量/配置文件、选定阶段、作用对象、读写输出及错误路径。互斥约束需要读到真正执行的检查及顺序，帮助解释多个无效选项同时存在时先报哪个错。

从 getopt/配置解析 → options 结构 → 校验/标准化 → 主流程 → 具体任务/SQL 生成一路追踪。一个字段被设置不表示后面使用；反向搜所有读取者，确认未被后续默认或模式覆盖。无参数、合法基线和最近非法组合是最先需要的三个路径。

## 执行阶段与一致性

| 工具阶段 | 需要回答的问题 |
|---|---|
| 连接与探测 | 会话参数、权限、版本检测、编码、客户端库如何影响行为 |
| 元数据/对象选择 | 包含/排除、依赖闭包、schema/name 引用、对象顺序 |
| 数据读取 | 快照何时建立/共享、并发 DDL/写入影响、流式/批量范围 |
| 输出/归档 | 文本/归档/目录格式、压缩、对象目录、校验、版本标识 |
| 恢复/装载 | 建对象、装数据、索引/约束、触发器、序列/权限、提交阶段 |
| 并行与结束 | worker 调度、依赖屏障、失败汇总、退出码、清理与残留 |

不是每种工具都有这些阶段；不存在要用入口范围解释。dump 成功、restore 成功和迁移结果等价分别判断。只看行数不能证明序列、权限、约束、编码或类型语义正确。

事务/快照调查应追到 BEGIN/COMMIT、SQL 生成、worker 连接、snapshot export/import（当前版本适用时）及错误返回。单事务与并行是否相容以源码约束为准，不能根据其他产品经验编造支持矩阵。

文本导入需要解释 delimiter/quote/escape/NULL 表示、编码、换行、日期/数值格式、坏行处理和 reject 文件。涉及类型解析/隐式转换时加载 compatibility；服务器内存/等待出问题时加载 memory/waits。客户端处理后的字段与用户原始文件字节不一定相同。

## 失败后究竟留下什么

按阶段记录 failure → 已产生的文件/对象/行/事务 → 未提交/已提交 → 自动清理 → 可重试单位。需要确认 close/flush/rename/删除临时文件、断开 worker、回滚或继续执行的顺序。

重试/恢复建议须回答：输入是否可重读、对象是否已创建、唯一键/约束是否存在、是否幂等、序列/权限是否改变、是否有重复装载/遗漏。工具未实现 checkpoint 就不能声称断点续传；有目录或日志也不代表可安全续传。

针对 clean、truncate、drop、禁用触发器等动作，研究其准确作用范围与失败状态再写规程。运行任何清理需在用户授权环境内；没有执行环境时交付可审阅计划即可。

## 区分性实验

使用小而有差异的对象集：依赖对象、约束/索引、序列、含 NULL/空串/分隔符/多字节文本的数据，以及与主题相关的类型。每次只改变相关选项或版本条件。

实验矩阵覆盖：合法基线、互斥选项、空输入、单个坏对象/坏行、中途 worker 或连接失败、重试后的结果。未做中断实验时恢复保证保持 open，不拿参数错误退出测试代替恢复测试。

核验保存：实际命令（脱敏）、二进制/两端版本、输入与归档身份、stdout/stderr/退出码、目标对象和数据差异、事务/残留状态。成功判据由研究目标决定，可能包括对象定义、行内容、约束、序列、权限和依赖，不能全部简化为 exit 0。

## 交付与挑战

`options_and_stages` 写参数决策表与阶段图；`consistency_and_dependencies` 写快照、对象顺序、事务/并行和语义依赖；`failure_and_verification` 写阶段残留、重试条件与结果核验。

用“同样报错，发生在校验前还是已提交部分对象之后”挑战恢复建议；用“源端/目标端模式不同”挑战结果等价。只研究了参数互斥时可以发布这个规则，必须保留完整导入导出、并行恢复和跨版本迁移尚未验证的边界。
