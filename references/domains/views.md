# 系统视图：从 SQL 定义追到字段生产者

与 [公共深度规则](../common/research-depth.md) 一起使用。学习单位是视图接口和具有独立语义的字段；DDL 列名和 SELECT 表达式只解释了链条的一部分。

## 确定真实接口

核对 schema、视图/表/内置函数、签名与返回类型，以及当前提交的安装/升级脚本和构建路径。区分本地接口、集群封装、历史表、实时快照和扩展视图。同名 SQL 函数的 overload、默认参数、节点侧实现都可能改变结果。

入口顺序：安装定义 → SELECT 的投影/过滤/连接/聚合 → 函数注册 → C/C++ 返回结构 → 读取的数据 → 所有相关写入和重置。构建脚本没有确认时，只能说明源码定义存在。

## 建立逐字段血缘

| 血缘层 | 每字段应记录 |
|---|---|
| SQL 层 | 输出名、类型、表达式、别名、cast、join/filter/aggregate 对行的影响 |
| 函数层 | 注册签名、tuple descriptor 序号、values/nulls 对应、SRF 迭代条件 |
| 状态层 | 结构体字段、共享/会话/线程/局部归属、初始化和写入者 |
| 变换层 | 枚举名称映射、单位换算、格式化、截断、异常值处理 |
| 可见层 | 权限、脱敏/置空、过滤、节点范围、参数开关 |
| 时间层 | 实时读取/缓存/快照、刷新/重置、采样一致性 |

先追任务相关字段，再展开足以解释 join/filter/范围的邻近字段。不能要求一次把宽视图所有列学完，也不能把几个已读字段的结论推广到整张视图。

类型不只看 SQL 声明，还核对 Datum 构造和 nulls 数组；序号、数组长度、tuple descriptor 与分支是否一致。SRF 多次调用时，状态在首次构造还是逐次读取？中途线程退出或列表变化怎样处理？接口若跨节点，追请求生成、远端执行、聚合、重复/缺失和远端错误。

## 权限与 NULL 是核心语义

分别列出：行不存在、行存在但列 NULL、空串、零、unknown 标记、权限拒绝和查询失败。每种情况回到生产分支；不能把 NULL 直接译为“没有等待/没有连接/没有资源”。

查权限检查实际使用的身份：调用用户、对象所有者、session user、角色成员或特定监控权限。区分 SQL 层 WHERE 过滤、函数内置空和整条权限错误；查 SECURITY DEFINER 或受控封装是否改变身份。不要向普通用户提供只有管理员才可见的结论保证。

状态读取可能使用锁、序列计数、屏障、复制重试或不一致快照。分别判断单条记录内部一致性、跨行一致性、跨视图/节点同一时刻；看到有锁不能推导整次查询原子一致。读不到时记录重试/丢行行为。

## 诊断含义须回到生产者

字段叫 wait_status 不等于包含 wait duration；字段名有 memory 不等于进程 RSS；计数为零可能是未启用、被重置、权限隐藏或确实没有事件。要解释这些差别必须读取 waits/memory/decoding 等主机制，而不是仅重述视图文档。

针对一个诊断问题，写出查询选择哪些列、依赖哪些关联键、为什么这些字段能区分假设。关联键注明线程/会话/进程/节点身份、复用和时效。不同接口标识相似不能直接 join。

## 验证设计

在隔离环境安排：对象出现、状态改变、对象结束；不同权限；相关开关开启/关闭；本地与集群（适用时）；统计重置前后（存在该操作时）。每次保存查询、返回类型、完整相关列、身份、时间和目标动作。

采样语句执行本身可能有代价或影响；根据生产者判断是否触发扫描/锁/远程请求，再给建议频率。无法读取目标环境时只交付 SQL 候选及版本/权限前提，不能编造查询结果。

## 交付与挑战

`definition_and_lineage` 写接口绑定和字段血缘；`visibility_and_consistency` 写权限、节点、快照与刷新；`field_semantics` 写单位/时间含义、NULL/零/无行及使用限制。对象页放接口，机制页放共用采样/统计逻辑，procedure 放采样规程。

复核时给出一个“相同查询不同身份”和一个“相同显示值不同真实状态”的区分案例；范围不涉及权限时可以用路径依据说明。尚未追到写入者的字段应保留缺口，不能只因返回列类型正确就称字段语义已完成。
