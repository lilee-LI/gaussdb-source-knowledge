# 错误与断言：检测点、成因与处理的分层研究

保留原错误 Skill 的 [完整流程](../../INTERNAL.md)、[语义复核](../../engine/source-error-learning/references/semantic-review.md) 和 [证据边界](../../engine/source-error-learning/references/evidence-and-recovery.md)。本手册补齐多领域框架中的研究方法，不能替代原有文章、客户证据和恢复契约。

## 报错身份与候选保留

以产品/提交/构建、SQLSTATE、产品错误号、message/detail/hint、检测点、操作入口共同定位。错误号与检测点不保证一对一，参数化文本也不能直接代表同一状态。保留同码异因、同文本异点、包装层重抛和服务端/工具/驱动的不同来源。

先判断这是 ERROR、FATAL、PANIC、WARNING、返回码还是断言；读实际宏展开、日志/协议映射、构建开关。仅有 Assert 的源码，不能推断发布构建会对外报同样错误。接收现场信息时先检索已发布且版本适用的知识，证据足够就给出能支持的判断，再补必要的区分信息。

## 从检测条件追到发生机制

1. 把触发分支写成精确条件，注明比较对象、边界、短路/前置检查和消息参数来源。
2. 逆查条件中的值：谁初始化、谁写入、何时失效、怎样转换、是否跨线程/事务/节点。检测点看到无效状态，不意味着检测函数制造了该状态。
3. 正向确认用户可达路径：SQL/工具/协议入口、签名或选项绑定、前置检查、模式/构建/权限；不能因为函数存在就断言当前环境能触发。
4. 读最近正常路径及异常传播：错误发生在哪个阶段，是否重试/重抛，事务/子事务怎样变化，锁/内存/文件/连接怎样清理，有无部分成功。
5. 提出竞争解释，选择最小区分证据。只有共同症状时保留候选，已有直接证据时给出该范围内的正面判断。

对于断言，明确被保护的不变量、对象别名/生命周期、并发顺序和检查前提。区分输入错误、内部状态违约、资源耗尽及内存破坏；不能仅因 Assert 失败就认定是某个已知缺陷。

## 用专业依赖补上因果段

| 检测条件依赖的内容 | 需要的研究 | 应带回错误文章的内容 |
|---|---|---|
| 转换后数值、日期、类型或语法状态 | compatibility | 输入绑定、转换/模式规则、非法边界和替代输入 |
| 等待/超时/取消、锁状态 | waits + views（需要观测时） | 排队/唤醒链、时限生产者、采样权限、取消清理 |
| 分配失败、上下文失效或增长 | memory | 所有者、分配规模、保留/释放、统计与证伪泄漏的依据 |
| 工具选项、导入阶段、对象依赖 | tools | 实际执行阶段、服务器错误来源、已提交状态和安全恢复前提 |
| slot、WAL、快照或插件状态 | decoding | 位点/确认关系、资源保留、异常及重启路径 |

辅助领域的存在只是调查线索。文章需写出该知识如何令本检测条件成立，并绑定适用版本；不能因为关联了“兼容性”页就宣称找到了根因。必要段未读完时记录 unknown 和下一项任务。

## 写出可区分的诊断与可复验的措施

原因表每行记录：候选原因 → 成立条件 → 支持信号 → 排除信号 → 所需最小观测。采集项必须有真实字段/日志/接口生产者、适用版本、身份权限、采样时机和失败含义；不要编造视图字段。

措施表每行记录：所针对原因、执行前提、作用对象、预期状态变化、副作用、失败/回退途径、成功判据。改 SQL、切换模式、加超时、增内存、重建 slot 等建议要分别核对相应领域语义；“错误消失”不等于数据结果正确或业务已经恢复。

诊断成立、措施执行、效果复验、防复发调查分别记录。能证实当前输入非法时可以明确解释，尚未查清为何上游产生此输入不应阻止这一结论；但不能据此断言历史唯一根因或永久解决。

## 挑战与交付

交付前按[错误文章阅读顺序](../error-article-presentation.md)组织文字：中文含义与贴近业务的例子在前，GAUSS/SQLSTATE 的意义和实测边界明确，关键术语先解释，原因与有条件措施随后，源码位置及深入实现放文末。该顺序适用于错误入口、关联场景、机制及规程；研究过程仍须完整深读，不以写得通俗代替因果和证据。

尝试构造同码另一检测点、同检测点另一上游原因，以及最接近的正常输入。对现场候选，说明哪个观测会改变排序。对修复，检查最近失败路径是否留有部分状态，复验是否覆盖结果而非只看返回码。

按 errors 注册章节存放检测/传播、上游机制、处理与验证；精确名称以 context 为准。机制内容进入共享机制页，错误对象页链接对应规则，场景页记录实际证据。研究接受不等于现场已执行；静态复核和运行实验分别落账。
