# 兼容性：从语义规则学到可预测的行为

与 [公共深度规则](../common/research-depth.md) 一起使用。研究对象是“特定输入和环境下的一条语义规则及其边界”，不只是模式判断语句。找不到 A_FORMAT 等关键字，也可能存在继承实现、共用规则、默认差异或缺失能力。

## 规划对象和入口

先区分语法接受、类型解析、执行结果、错误行为和客户端显示；“支持某函数”不足以描述这五层。对 SQL 样例记录表达式、参数实际类型、显式/隐式转换、输出类型、模式、会话参数、字符集/排序规则、时区、构建/插件、执行入口。只在相关时展开某个维度，不能把未调查写成无影响。

对领域全景学习先读 [语义版图与覆盖矩阵](compatibility-map.md)。对格式化函数，另读 [固定提交的路径示例](compatibility-formatting-case.md)，以它学习研究方法，不能把该例结果套给其他函数。

从语法、类型和函数族建立主题，不以 grep 命中数定义主题：解析/名称解析，数值/字符串/日期与时间，NULL/空串，比较与排序，集合/聚合，DDL/事务，PL/异常，工具与协议。每个主题先列可研究规则、已有证据和空白，再选一个可以闭合的小范围。

## 建立完整路径

| 层 | 必须追到的内容 | 常见误判 |
|---|---|---|
| 可达入口 | SQL 语法节点或内置/扩展注册、schema 搜索、候选签名 | 同名 C 函数就是用户实际调用 |
| 绑定 | 重载选择、unknown 字面量、类型类别、隐式转换、默认参数 | 两个文本相似 SQL 走相同实现 |
| 前置处理 | strict/NULL 策略、编码、typmod、预处理、常量折叠 | 函数体未处理 NULL 就代表不支持 NULL |
| 核心语义 | 数据表示、算法、舍入/截断、溢出、格式解析、比较规则 | 模式分支之外全都兼容 |
| 选择条件 | 模式、配置位、编译开关、插件、版本、权限和调用上下文 | 只有 sql_compatibility 决定行为 |
| 输出/异常 | 返回类型/精度/编码、SQLSTATE、错误阶段与事务影响 | 同一显示值就语义等价 |

先读注册和调用绑定，再读具体实现；测试专用 catalog 不是当前构建注册证据。遇到重载链，至少追完当前签名和一个最相近签名，记录哪些规则共用、哪些分开。遇到 parser/coercion 配置，继续追定义、默认值、作用域、设置时机、是否可变及生效阶段。

兼容条件的搜索包括相等、不等、switch、宏和辅助谓词、配置掩码、缺省路径；同时从用户入口正向追踪。一个正则没有命中不能证明没有兼容性差异。候选发现器负责入口清单，研究者负责遗漏调查。

## 把条件整理为规则

每条规则记录：输入域 → 绑定入口 → 路径选择条件 → 处理规则 → 结果/错误 → 不适用边界 → 支撑证据。多个条件组合时画决策表，区分解析阶段已固化的选择与执行阶段重新读取的选择。

对于缓存和预编译，找缓存键、值中保存了什么、失效/重解析时机。模式或参数变化后是否仍走旧规则必须有路径依据；仅看缓存存在不能推导“模式串用”。对于优化器简化，核对常量表达式与列值表达式是否可能在不同阶段求值。

数值规则读到精度/标度、中间表示、舍入点和溢出检查；时间规则区分 date/timestamp/timestamptz/interval、时区转换与显示、边界历法和格式标记；字符规则区分字节/字符长度、空格/空串、编码和排序；DDL/事务规则追到锁、目录变更、提交/回滚及失败状态。不要把这些主题全部塞进一次函数研究，按任务声明展开相关部分。

## 设计能证伪的用例

从实现的比较、索引、状态、范围检查和错误分支生成边界，而不是先罗列大量 SQL。先做单维区分，再做有因果依据的组合。

| 维度 | 优先选择的区分方式 |
|---|---|
| 类型和重载 | 显式定型对照字面量；同名相近签名；类型边界两侧 |
| NULL 与空值 | SQL NULL、空串、空白、缺省参数分别建例；先查 strict 和模式规则 |
| 范围与格式 | 阈值前/等于/后，合法格式与最小非法变化，token 与引号文字 |
| 参数和状态 | 每次只改变相关模式/参数；会话/语句级设置与重新解析分别记录 |
| 执行阶段 | 常量/列值、直接语句/预编译、首轮/缓存复用，确有分支时才组合 |
| 错误 | 正常值与进入最近检查点的输入；核对错误阶段/码/文本/副作用 |

每例保存目的、SQL、前置状态、该版本静态预期、预期依据、实际输出及判定。还未执行时 actual 留空或 not_run；不能把源码推导抄为实际结果。清理步骤须恢复测试环境，前提不明确时先保留计划。

Oracle 或其他目标侧要求独立的版本、文档或真实运行证据。与文档对照只证明文档范围；与一次运行对照只证明该输入和环境。没有目标侧材料时，只能写本实现语义与待核对问题。用户没有要求外部对照时，可先完成本地源码研究。

## 知识组织与后续诊断

函数/语法对象页放签名、入口和能力边界；规则/机制页放绑定、转换、算法及模式选择；场景页放具体差异的输入、路径、竞争解释与处理；procedure 放可复验 SQL 和条件。函数族索引连接共享规则，避免每个报错页复制一份转换规则。

向错误领域提供：该 SQL 如何进入检查点，哪个条件令数据无效，最近替代原因怎样区分，改写/参数变更会改变哪些语义。向工具领域提供：服务端版本、模式及输入格式如何影响导入。修复建议必须解释语义变化，不能用“切换模式即可”作普遍措施。

## 本领域的充分性复核

可接受的有界研究应能从一个未照抄的近邻输入推导其入口、条件和预期分支，或明确指出决定它的缺口。复核时主动尝试：换重载、换引号、换隐式转换、换一个条件、换错误阶段。

`inputs_and_binding` 保存入口/签名/绑定和作用域；`conditions_and_branches` 保存规则/配置/替代实现与读写时机；`behavior_and_counterexamples` 保存正常与反例、静态预期、实际验证及目标侧证据边界。未读注册、未确定转换或未确认目标侧行为，按声明范围列为 gaps；不能用“兼容模式”四字跳过。
