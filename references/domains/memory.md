# 内存上下文：所有权、生命周期、分配器与增长解释

与 [公共深度规则](../common/research-depth.md) 一起使用。上下文名称、树位置和一次统计不能单独证明内存泄漏。研究需同时连接对象生命周期、实际分配/释放和观测口径。

## 先明确对象和量

区分 MemoryContext 对象、其中的 allocation/chunk、allocator block、自由链表/保留块、共享内存和操作系统页。对于使用内存的业务对象，还要记录其逻辑所有者、存放指针的位置和预期存活期。

声明进程/线程/会话/语句/事务/缓存范围，核对线程池或并行任务是否改变归属。上下文父子关系负责什么清理规则，要读当前实现；不能把父对象仍活着当作子分配一定合法。

## 从创建者到最后一次使用

| 路径 | 需要核对 |
|---|---|
| 创建 | 创建入口、父上下文、allocator 类型、大小参数、命名、初始化条件 |
| 分配 | palloc/显式 context alloc/原生 malloc 等真实入口、当前上下文如何选择、尺寸来源 |
| 使用 | 指针保存、复制或转移、别名、跨上下文引用、访问期间的生命周期 |
| 复用 | 缓存键、容量上限、淘汰条件、自由块复用、每轮是否累积新对象 |
| 回收 | pfree/reset/delete/回调、子树顺序、异常清理、资源所有者/事务钩子 |
| 观测 | allocated/used/free/peak/RSS 分别来自哪里、包含什么、多久更新 |

`MemoryContextSwitchTo` 需读内联/非内联实现和调用者保存/恢复 old 的方式；切换只改变分配目标时，不能解释成内存搬迁或释放。遇到方法表须追到当前 allocator 的 reset/delete/alloc/realloc 实现。区分 Reset、ResetAndDeleteChildren、Delete 等当前版本实际存在的 API，不能凭名称假定子树行为。

错误路径重点查 PG_TRY/PG_CATCH、事务 abort、线程退出和回调执行顺序。上下文重置不自动代表文件、锁、外部库资源都释放；查注册回调或独立 ResourceOwner。临时切换后 ERROR 跳转是否恢复 CurrentMemoryContext，需要调用链证据。

## 读分配器和统计口径

追 block/chunk 元信息、大小类别、对齐、keeper/初始块、自由链表、大块特殊路径、realloc 复制/原位逻辑和上限检查。只有研究目标涉及这些部分才深入，但要足以解释观察到的保留量和分配失败。

为每个指标建立账本：统计主体、计数更新点、是否含 header/对齐/空闲/子上下文、peak 是否重置、采样同步和单位。逻辑对象释放、上下文 available 增加、allocator 向系统还页和 RSS 下降是不同事件，分别提供证据。

OOM 还需区分：请求本身过大、整数溢出/尺寸算错、数据库限额、allocator 失败、系统/容器限制或并发峰值。错误信息中的请求尺寸不是泄漏证明，切勿直接给出“加内存”作为唯一处理。

## 用增长形态区分假设

| 假设 | 源码调查 | 最小区分观测 |
|---|---|---|
| 有界缓存/高水位保留 | 容量/复用/淘汰、keeper block | 相同工作负载多轮是否趋稳、used 与 allocated 是否分离 |
| 生命周期过长 | 创建范围和回收触发 | 语句/事务/会话结束后目标子树变化 |
| 真正丢失回收路径 | 分配可达、所有者丢失、遗漏 cleanup | 反复相同路径持续增长，且预期释放点未回收 |
| 悬空引用/重复释放 | reset/delete 后使用、别名和并发 | 受控触发、地址/调用栈和构建检测输出 |
| 正常业务积压 | 活跃对象数、队列/事务/解码状态 | 处理积压或结束长事务后是否下降 |

这些只是调查方向，不能依据曲线形状直接定性。内存上下文统计无法解释的部分，应继续查原生堆、共享区、映射或外部库，并保留范围未知。

## 验证与安全处理依据

隔离环境记录同一构建、输入规模、并发、轮次及上下文标识，采集 baseline、执行后、逻辑清理后、再次复用后的量。每次采样同时注明当前活跃对象数或积压量，避免把负载变化误判为回收问题。

需要 sanitizer、内存调试或断点时，核对目标构建是否支持并记录额外开销。不能从生产查询中的一个上下文名就提出随意 reset/delete；先证明所有引用已失效、无并发使用、外部资源清理完整。建议降低批量/并发也要指出它作用于哪段分配规模。

## 交付与充分性

`ownership_and_lifetime` 写所有者树、指针关系和活跃期；`allocation_and_cleanup` 写真实分配器和正常/异常回收；`accounting_and_growth` 写指标口径、竞争假设和区分实验。

复核至少挑战“reset 后 RSS 不降”和“事务结束仍增长”这类近邻问题中与本任务有关的一项。若不能解释，应列下一步的写入/回收/采样定位，不能用通用内存常识补上未读路径。解码重排、工具批量和错误清理可引用该机制，具体负载结论仍由场景证据支持。
