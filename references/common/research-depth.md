# 源码研究的深度与跨领域依赖

此规则与主领域手册一起使用。目标是建立能够解释新问题的知识：从输入推到行为，从观测倒查状态，给出可以区分相近原因的证据。阅读量、调用层数、候选数量和文章长度不作为完成标准。

## 先确定这次研究要解释什么

区分三个范围：一个执行路径或报错点；一个对象/函数族的若干语义规则；整个领域的覆盖规划。小任务可以接受，但不得把一条路径写成整个函数族、产品或领域已学完。

声明产品、完整提交、源码范围、构建对应关系、对象签名、操作入口、模式与运行环境。只有源码时，记录构建对应关系 unknown；源码中的存在、目标构建可达、运行环境可见分别判断。openGauss 的静态结论不能直接改称商业 GaussDB 或 Oracle 结论。

开始研究时建立以下工作表；最终把与声明有关的内容纳入 question_answers、domain_findings、claims、gaps 和 validation_plan。表格可以放在研究笔记中，不必重复创建同义 Wiki 页面。

| 工作表 | 每行至少记录 | 用来回答 |
|---|---|---|
| 路径与状态 | 入口、调用条件、读写对象、状态前后值、正常出口、异常出口、证据 | 这个行为怎样发生 |
| 条件与分支 | 输入/模式/配置/权限/构建条件、替代路径、可见差异、未读分支 | 换一个条件会怎样 |
| 假设与区分 | 假设、成立前提、支持证据、反证、最小区分输入或观测 | 为什么是这个解释 |
| 领域依赖 | 领域、required/not_involved/unknown、待解释问题、判定依据、依赖结果 | 还缺哪一段专业知识 |
| 覆盖与验证 | 已解释规则、已读分支、未读分支、源分析/运行/对照状态、剩余风险 | 结论能用到哪里 |

## 深读的实际动作

从对象声明、SQL/命令入口或报错检测点向两侧展开。向上追到用户可达入口和输入绑定；向下追到决定行为的数据、算法或状态写入者。调用图只用来导航，必须核对参数、条件和调用者上下文。

遇到状态读取，找初始化、所有相关写入、重置、销毁及同步；遇到包装函数，读被调用的具体实现；遇到宏、方法表、内联替代或插件回调，确认当前构建选择；遇到缓存，分别解释首次构建和复用时哪些决定被保存、哪些每次重新计算。不能以同名符号或一条 grep 命中补全未读的因果边。

在已解释路径附近主动找反例：相同输入不同类型、相同错误不同检测点、相同字段不同权限、相同计数不同重置周期、相同失败不同提交阶段。选择能区分当前两个解释的例子，避免只增加同类正例。

遇到证据冲突，先比较产品/提交/构建/入口/对象签名和采样时刻，再研究实现变化。保留冲突及来源，不用“通常如此”抹平冲突。源码测试说明作者覆盖了某个用例；未在目标环境执行，不能写成当前验证通过。

## 按因果缺口加载辅助领域

主领域负责提出和整合问题，不垄断所有解释。下列信号触发依赖调查：

| 研究中发现 | 应加载的领域及具体问题 |
|---|---|
| 错误由类型转换、语法或模式分支触发 | compatibility：输入如何绑定、哪条语义规则令条件成立 |
| 等待、超时、阻塞或取消 | waits：何时进入/退出、时长如何定义；views：观测字段由谁生产 |
| 内存不足、持续增长、对象失效 | memory：所有者、分配路径、生命周期及统计口径 |
| 工具报错或导入后结果差异 | tools：选项和执行阶段；compatibility：服务器实际解析/转换规则 |
| 解码中断、WAL 堆积或消费差异 | decoding：位点/快照/确认链；memory/waits/views：相应资源和观测 |

required 要写具体问题，不能只勾选领域。not_involved 要有路径或范围依据；尚未读到相关实现应记 unknown。随着证据扩展更新判定。依赖简单时直接用 supporting_domains 联合研究；可以独立复用的机制另建任务，用 dependencies 绑定接受的具体结果。规划后发现必要依赖，应创建扩展任务或依赖任务，并在原任务保留缺口，不能修改已冻结的任务或把未知项改成 not_applicable。

必要依赖未解决时，可以发布适用范围明确的机制事实或收集规程；有关该缺口的确定根因、恢复保证或兼容性等价结论保持开放。关系边表示检索关联，实际结论还需要正文中的条件、推导和证据。

## 交付与语义复核

事实要能在引用中直接找到；推导列出前提和推理；候选解释保留区分条件。每个行动写触发条件、作用对象、预期变化、影响与复验方式。纯阅读任务可以交付运行计划，但状态必须是 not_run。

语义复核时，用这些问题挑战自己的结论：

- 删掉函数名和错误文本后，是否还能从条件与状态解释行为？
- 换用最近的替代入口、类型、权限、模式或异常路径，哪些结论仍成立？
- 关键字段的生产者、单位、生命周期是否真的读到？
- 是否把静态可达、运行发生、现场唯一根因或产品等价混为一谈？
- 哪个尚未执行的输入最可能推翻当前解释？它是否已记录为计划或缺口？

accepted 仅表示本任务约定范围经实际复核；领域充分性另看覆盖台账。每轮研究补规则、反例或证据，或明确关闭一个缺口。连续只新增相似正例时应转查替代路径与竞争解释，不以文章数量宣称饱和。

## 方法资源与历史任务

新 study plan 将总入口、公共规则、所选领域 Skill 及注册手册的字节哈希写入 spec，并保存冻结副本；study context 返回这些副本的位置和用途。开始任务先读 required 资源，按条件读取专题资源。引用手册是方法依据，不能充当数据库行为的源码证据。

旧任务没有此绑定时，context 明示使用当前规则作参考；不能宣称旧研究已经按新手册重新完成。方法变厚不会自动提升已有文章的覆盖和验证状态。
