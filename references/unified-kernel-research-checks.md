# 数据库内核公共研究检查

合同：unified-kernel-checks/v1。每个特性按真实范围判断 required / not_involved / unknown；这里给出问题和证明义务，不预填产品行为。

| 检查 | 必须问的问题 | 有依据的交付 |
|---|---|---|
| algorithm_contract | 算法的输入、前置、结果和不变量是什么？改写是否保持语义及顺序、分布等物理属性？估算与运行协议如何区别？ | claim、前置/后置契约、最近正常/失败反例、复杂度或资源假设 |
| transactions_visibility | 状态属于语句、事务、会话还是全局？快照、提交、回滚、子事务或权限变化怎样影响可见性？ | 生产/消费与可见范围、提交及错误边界、适用条件 |
| concurrency | 哪些线程/进程/节点共享状态？锁、原子操作、锁序、发布与唤醒的先后怎样保证不变量？ | 具体同步对象与状态转换、并发交错反例、未建立的保证 |
| durability_recovery | 哪些数据只在内存，哪些需要记录/刷新/恢复？失败发生在持久化前后分别如何？ | WAL/持久化与恢复关系、可重复/遗漏的边界、未读恢复路径 |
| cache_invalidation | 哪些选择在缓存/计划构建时固化，哪些执行时重算？缓存键、失效、重扫与对象寿命怎样联系？ | 建立/复用/失效/重建契约、旧状态不可复用的条件 |
| build_scope | 宏、编译选项、架构、插件、节点角色及部署方式怎样选择路径？ | 定义与展开、配置下实际解析/未解析、调用候选及未知构建；不把源码存在升级为任意构建可达 |

必要领域依赖没有解决时，先限制相关结论的适用组合，并建立具体补学任务；仍成立的有条件事实可以单独交付。无需为每个模块复制一份内存、事务或错误机制。

源码研究要追到状态初始化、相关写入、最后合法读取与清理，区别直接调用、数据阶段、状态转移和异步消息。反例应能区分两个解释；C/C++ 的语言语义、编译假设及宏控制流分别核对。

当前所有实验、并发场景和恢复场景都是待运行的验证设计。没有实际二进制、输入和执行回执，不声明运行发生或恢复保证。
