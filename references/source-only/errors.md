# 错误与断言：纯源码研究

与完整错误领域手册联合使用，本页约束不运行数据库时怎样把原因研究做实。

## 入口到检测点

先对齐 GAUSS 编号、SQLSTATE、正文、DETAIL/HINT 与实际检测点族。由文案向上追用户入口和输入生产，向下确认报错前的状态、清理及传播。区分检测位置、可达原因和现场唯一根因。

paths 写正常路径与失败出口，rules 写触发谓词、错误类别和状态影响。branches 至少读一个最近相邻检查点，例如格式失败/范围失败、NOWAIT/等待超时、非法尺寸/资源失败。

## 反例与依赖

正常案例满足全部前提，边界取检查阈值，反例只改变一个关键条件以区分竞争解释。同 SQLSTATE 不推导同一检测点，同文案不推导同一原因。hypotheses 写能排除当前候选的条件。

类型/模式交 compatibility，等待/取消交 waits，字段生产交 views，尺寸归属交 memory，工具输入交 tools。依赖要有答案或具体缺口。

文章先解释错误标识与术语，源码置后。断言研究交付不变量及相关写入，不触发生产断言。条件处理说明前提与语义影响；所有案例 execution=not_run，没有现场证据不报唯一根因。
