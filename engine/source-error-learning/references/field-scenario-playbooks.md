# 现网场景、判别采集与有条件处理

源码研究要输出可被现场使用的方案，但 source_only 阶段不采集、不执行、不确认客户根因。以下所有卡片是条件知识；应用于工单时仍需核对版本、身份、时间、语义和变更授权。

## 场景卡

每个场景写清：入口、参与对象/会话、触发条件、用户能看见的现象、候选成因、易混淆解释、改变判断的关键证据、采集与动作引用、适用边界。按“诊断或动作会不同”拆场景；不同客户名、不同常量不能独立构成新场景。多个原因可以共同作用，场景不必互斥。

状态有四种：conditional_playbook（已有源码支持的有条件规程）、needs_evidence（尚需材料才能形成规程）、source_gap（机制未闭合）、no_safe_action（当前没有可安全推荐的操作）。后两类必须明确下一步，不能为了完整率勉强填处理命令。

例如数据转换错误可区分直接文字输入、应用绑定值、批量导入的文本与列映射、目标列/表达式隐式转换等入口；这些只是研究维度，是否会进入同一错误及怎样安全修复，必须读对应源码。不能从一个报错字符串直接断言客户数据应删掉某个字符。

## 判别项必须能改变判断

每个判别项提出一个具体问题，绑定支持/排除哪些成因、从哪些采集取得值，说明三种结果：

- 支持：观察到什么值和前提，使该机制成因在本范围内得到支持；是否仍需第二项证据。
- 排除：在身份、版本和时点满足何条件时，观察到什么可排除此解释。
- 未知：材料缺失、不同会话、时间漂移、权限失败、NULL/空行、字段不支持时，继续收什么或停止哪项动作。

支持和排除的成因集合可以不同，也可能没有可排除项。不能因定义了一个布尔字段就假定已有事实。当前配置不能自动证明报错时配置；可见的一个锁持有者不能证明完整历史阻塞链；查询成功不证明有权限看见全部行。

每个原因与最近竞争解释需要至少一个有效区分事实。如果现有观测只能看到公共结果，就明确“尚不能区分”，补原始输入、会话/事务上下文、历史日志或更低层材料。多个成因共存时不要按第一个命中提前停止。

## 最小采集卡

| 项目 | 必须写清 |
|---|---|
| 目标/位置 | 具体节点、数据库、会话/事务/工具进程；是否必须原连接 |
| 身份/权限 | 最小可用权限、受限结果、需要谁配合，不能默认 root/超级用户 |
| 内容 | 版本支持的 SQL/命令；或明确要用户提交哪个日志片段、绑定参数/结构定义 |
| 时点 | 报错前后/仍在等待时/原事务内；跨连接、重连、回滚会丢什么 |
| 输出 | 要保留的字段、原始格式和关联标识；足以支持何判断 |
| 代价与隐私 | 扫描/锁/负载、敏感文本、脱敏后必须保留的结构/对应关系 |
| 空值/失败 | 无行、NULL、权限失败、字段不存在分别意味着什么 |
| 来源 | source_derived（源码推出的采集）或 unknown；本轮不导入真实现场材料，均未运行 |

从最小低成本信息开始，按判别分支追加，不能默认整库扫描或全量日志。SQL 未在对应源码中确认语法/字段时，只能写未知采集及下一步，不可作为 conditional_playbook 的已准备采集。手工材料请求可用 language=material，命令文本说明具体所需材料，无需伪造 SQL。

失败事务中许多查询不可继续；若需换连接、回滚或重连，必须说明它如何影响现场证据。不要把会改变现场的动作混进只读采集。

## 措施是独立推理对象

同一成因可有多项措施，不同场景可共用措施，但前提分别核对。类别区分 recovery、workaround、durable_fix、prevention。不是每个错误都需要四类；缺少安全措施允许停止在明确缺口。

一项合格措施包含：适用场景/成因、证据成立条件、排除条件、对象和负责人/权限、逐步操作、预期状态改变、业务语义不变量、影响、回退、失败出口及复验。与场景无关的“通用建议”不计针对性解决方案。

| 常见提案 | 必须额外证明 |
|---|---|
| 清洗/删除/替换/转换数据 | 格式及业务意义、异常样本隔离、可逆性，不能损失小数/符号/NULL 意义 |
| 重试语句/事务 | 错误可重试性、正确事务边界、幂等性、退避/次数、外部副作用与失败收尾 |
| 调高限额/等待时间 | 真正瓶颈、作用域、可承受负载、是否只是延迟同一失败 |
| 改 schema/对象/权限/模式 | 依赖、数据与解析语义、安全边界，原会话是否生效及回退 |
| 结束会话/重启服务 | 业务所有者、影响范围、事务/复制/持久副作用、证据保留、恢复条件 |
| 导入或逻辑解码重跑 | 快照、位置、事务边界、去重/丢失风险、恢复点一致性 |

“把报错 if 变 false”不保证业务正确，例如给默认值、丢行或强制截断可能消除错误但破坏结果。措施必须解释切断的因果链，不能靠一次错误消失证明安全。

## 复验与反例

至少两个独立层次：检测条件/错误是否消失；业务结果是否符合语义不变量。另按相关性核对事务状态、数据完整性、锁/资源/复制等副作用和防复发信号。

每个源码支持的原因设计触发与最近正常反例。每个可处理场景设计错误措施/不满足前提的反例，说明预期为何失败、会产生什么错误或副作用。案例写输入、预期路径/结果、推导链和 evidence，execution=not_run；不要填实际耗时/成功输出。

身份/版本未绑定、判别不足、语义不明、回退缺失、不能控制影响范围时，输出待补信息或无安全方案及下一步。未知不是排除，源码合理不是现场已证实，规程可读不是动作已经执行。
