# 现场证据边界与事务恢复审查

用于支持 Agent 综合现场材料和形成处理方案。它是推理约束，不是某个错误的固定答案；具体机制、SQL、版本和业务前提仍来自实际知识与现场。未涉及事务的故障无需套用事务步骤。

## 先限制每个命题的证明范围

形成答复前，为关键结论核对：原始观察/声明、实例与对象/会话身份、观察时刻或覆盖区间、适用机制、尚缺条件。对外简要给证据和限制，不输出内部思维过程。

1. **当前观察不自动回溯。** 事务开始时间不是锁取得时间；两次快照中同一事务持有同一锁，不证明两次之间连续持锁，更不证明从事务开始一直持锁。晚采锁行可识别采样时的冲突候选，不能单独认定原错误时刻的唯一阻塞者。
2. **空结果的范围仅是实际观测范围。** 事后没有等待行，只能说采样时未见等待；不能排除错误时已经退出队列的请求。NOWAIT 自身请求的清理也不证明其他历史请求不存在。若无法取得事件时轨迹，保留该历史歧义；已有当前冲突持有者也不消除它。
3. **时间连续性需要额外证据。** 完整命令记录、独占连接控制声明、同会话/事务标识、源码生命周期可加强历史解释，但客户端声明仍是声明；明确条件和来源，不说成独立服务端审计。不得将 BEGIN 时刻写成随后语句精确取锁时刻。应用为何漏收尾，需要应用路径证据，不能仅凭 idle 状态确认连接池或代码缺陷。
4. **NULL、缺行、隐藏字段和反证不同。** 原样保留 NULL；状态标签和时间戳是不同字段，未核对该构建的实现或实测，不能从手册概述推出“某状态下字段必非空”的不变量。特别是失败事务状态与 xact_start=NULL 不能仅据此判材料矛盾；也不能只靠 NULL 断言事务块已经恢复。必要时最小补查版本/字段实现，不为解释一个 NULL 强令整包重采。
5. **更强结论需要更强证据。** “已确认”“排除”“唯一”“一直”等措辞需有覆盖对应身份、时段和竞争解释的材料；否则写当前观察、条件性解释或仍未知。源码证明机制可达，不能替代客户事件证据。模拟输入只能支持条件推演。

当前锁库存也不是完整事务历史：只看到 AccessShareLock、没有观察到写锁或行锁，不能证明事务只做过读取、没有其他对象/函数副作用或回滚影响较小。不要设计“再查全部锁来证明无写入”的伪判别采集；完整相关语句/写入/保存点与业务影响仍需拥有者材料。对任何排除或业务影响结论，都尝试构造一个与当前观测相容、但结论相反的合法历史；存在这种历史就不能作充分证明。

## 足够证据应当推进诊断和结案

证据边界约束的是命题强度，不是要求所有事实都经独立审计才能回答。可信且身份匹配的客户原始记录和完整性声明可以作为有条件的诊断依据；注明依赖该声明即可，不能无限退回“只是声明，仍无法判断”。已识别的一个原因足以导致错误，不必先证明它是历史上唯一的原因，才能给出诊断和有前提的处理。

例如同一原连接的完整、独占事务记录为 BEGIN、SELECT，随后未结束事务；源码说明该读所取关系锁保留到事务结束，快照又显示同对象的已授予 AccessShareLock。对另一个连接的 AccessExclusive/NOWAIT 失败，可说明：在完整记录和身份连续性成立的条件下，未结束读事务保留的冲突锁构成足以导致该失败的原因。不要从 BEGIN 推算精确取锁时间，也不要声称排除了所有历史并发请求。后者不妨碍前述有条件的充分原因成立。只有晚采快照而没有这类历史材料时，仍限于当前候选。

按实际任务分别判断，不笼统标成“仍未闭合”：

| 维度 | 可结束本阶段的证据 | 仍未具备时的下一步 |
| --- | --- | --- |
| 事件诊断 | 现场身份、操作和机制连成因果链；必要条件受记录支持或明确依赖已提供声明 | 只收集能改变原因/措施选择的缺口，不追求历史唯一性 |
| 措施执行 | 各动作的原连接、操作、时间和应答已回传 | 点名尚缺哪个动作的结果；已有意图和计划不是执行结果 |
| 本次恢复/复验 | 原操作按原语义成功、所有本次参与事务按选定边界收尾，身份、状态、相关锁和业务检查相互一致 | 原操作成功但未收尾应明确“成功持锁、尚待释放”，给出立即收尾和需要返回的最小结果 |
| 防复发调查 | 应用事务边界/代码路径或部署变更及长期效果已有证据 | 单列后续调查；不阻断已证实的本次恢复，也不把一次成功升级为永久修复 |

资料足够时给出明确状态和简短证据链。复验成功、收尾和范围都已证实时，可以说“本次加锁测试已闭环/该次操作恢复已验证”，同时限定未执行维护写入或未验证永久修复。反之不能用“方案自查通过”冒充执行闭环。

模拟数据的 before/after 可支持“在所给模拟记录中，诊断与恢复流程已闭环”；不得说成真实数据库实测。真实用户回传可在注明来源的条件下完成支持工单判断，无需 Agent 自己连接数据库。每个剩余未知需解释是否会改变当前处理/结案；不改变的放到后续调查，不能全部列为本案阻断项。

## 每个动作独立核对资格

对每个被操作的原连接分别核对身份连续性（实例/库、用户、PID/sessionid、backend_start、当前事务）、完整相关事务内容/保存点、拥有者业务意图、允许动作及禁止条件。持有方和失败请求方是两个独立对象；一方选择回滚不授权另一方回滚。最近 query 不是完整事务记录。

连接身份和事务状态也不能混同：state 变化可发生在同一连接内，不能由此断言连接重建；backend_start/PID/sessionid 等身份变化与事务切换分别判断。尚未提供的启动时间不得补成另一连接的值。现有输入已足够确定下一步只是拥有者补充时，不追加无助于该缺口的监控SQL；动作前的身份/当前状态复核放在前提齐备后的计划内。

内容或意图缺失时，先具体询问该拥有者，再给条件方案；不在通用采集中夹入事务结束。已提供明确选择且身份/范围仍适用时，直接使用，不重复索要同一授权。观察连接不能代替原连接结束它的事务。连接已经重建、事务已切换或有新工作时停止套用旧选择。

如果输入明确说“完整事务内容尚未提供”，几条客户端 SEND/RECV 或最近 query 仍是片段，不得自行补成完整记录。分别请每个拥有者确认 BEGIN 以来所有语句、写入/保存点及其结束选择；尚无选择时用中性问题询问，不把“请确认执行 ROLLBACK”当作业务意图核对。**任一拟操作事务的内容或意图缺失时，本轮停在具体补问/只读采集，不发布回滚、提交或重试操作步骤。** 可以解释后续处理方向，拿到前提后再展开完整方案。

用户限定只做加锁测试时，方案只做原加锁和已选收尾，不插入“然后做维护”等业务写入选项。动作与业务范围一致是独立条件，不能因后续提供了回滚意图就擅自扩大测试范围。

## 有事务重试的方案必须闭合所有出口

明确原操作、连接、重试次数/总时限、退避、每次失败的清理、成功清理、观察失败/用户中止以及最终检查。不要把几个 SQL 连成无条件批处理；中间结果决定下一步。

| 阶段 | 必须给出的分支和边界 |
| --- | --- |
| 准备 | 核对当前身份和动作资格；按业务选择结束遗留事务，恢复失败请求事务。不得在未知事务上直接 BEGIN 或重试。 |
| 每次尝试 | 已确认干净的原连接新开事务，执行原语义的操作。保留用户要求的锁模式、NOWAIT、参数及幂等约束。 |
| 原操作失败 | 保存错误/时间；按已选业务边界在**本次原连接**结束这次失败事务（通常 ROLLBACK；仅在存在合适保存点且获准时用保存点恢复）。确认恢复后才退避/新开下次事务。达到次数/时限或放弃，也要收尾。清理失败或结果不明时停止重试，补证/升级，不盲目连发命令。 |
| 原操作成功 | 先复验实际效果及业务范围。只做加锁测试且已选择 ROLLBACK 时，观察实际授予的锁后在该原连接显式 ROLLBACK。不能擅自添加维护写入或 COMMIT。 |
| 成功后的观察失败/中止 | 无论监控查询失败、超时或用户放弃，仍按已选方式及时在原连接收尾，避免强锁遗留。清理无法确认时明确未知、停止并联系拥有者，不声称已释放。 |
| 最终复验 | 复查相关原连接的身份连续性、最终 state/事务字段及目标锁；结合清理应答，不能靠 xact_start=NULL 单字段证明恢复。观察失败与业务失败分开。强锁保留时观察连接只查监控目录，不从另一连接读目标表；业务读放在释放后。保存原操作与业务预期结果、错误及剩余风险。 |

人为执行的方案也应像 try/finally 一样写清收尾责任。回滚应答、锁消失、原连接状态和原操作复验是不同证据。没有 after，措施效果是“待执行/未验证”，但事件诊断仍可在证据足够时完成；已有 after 则逐项判定，不固定回复“待执行”。一次成功只证明本次范围，不证明长期修复。

完整失败方案还包括：非预期错误保存原始错误，在已核对的原连接按已选边界收尾后停止，不按可重试错误盲目重发；通信结果不明先核对，不能把未知操作当作确定失败。最后一次失败收尾后不再退避；N次尝试至多N−1次退避。一方清理失败或出现新冲突，只停止新的业务/加锁尝试，不能无声遗漏另一方仍适用、已获选择的事务收尾；无法安全确认就逐连接标未知并联系拥有者。

动作前重新用数据库/schema/名称绑定当前对象OID，而非仅把旧OID写进锁查询；提供实际绑定SQL或明确复用前文哪条。最终检查以本次参与连接/事务的目标锁已释放为条件，不能要求整个对象锁查询为空；其他会话可持有相容锁。新冲突、其他相容锁、本次清理失败分别判断。成功后观察实际取得锁的对象身份/模式，与原请求一致，收尾应答和两个原连接正常空闲/无打开事务等共同确认恢复。

## 发布答复前复核

逐项核对：命题时空边界、竞争解释、字段语义、每个动作的资格、全部失败/中止出口、成功及最终复验、执行状态、引用，以及证据足够时是否实际推进诊断/结案。发现实质错误必须修订，不能用检索成功或引用齐全抵消。若宿主增加分离上下文的模型复核，绑定实际对话、实际返回的来源、候选答复哈希和逐项结论；这是模型复核，不能称独立专家审核。拒绝/返修记录保留，复核超时或仍不通过不发布未通过的处理方案。
