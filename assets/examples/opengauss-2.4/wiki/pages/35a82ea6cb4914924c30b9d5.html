## 行为和入口
- 入口与私有状态（geqo_main.cpp:48-81）：`RelOptInfo* geqo(PlannerInfo* root, int number_of_rels, List* initial_rels)` 先把栈上 `GeqoPrivateData priv` 的地址写入 `root->join_search_private`，把 `initial_rels` 存入 `priv.initial_rels`，再以 `u_sess->attr.attr_sql.Geqo_seed` 调用 `geqo_set_seed`。GeqoPrivateData 定义在 geqo.h：`{ List* initial_rels; unsigned short random_state[3]; }`，gimme_tree 依赖该槽位取回基表列表，geqo_rand 依赖 random_state。
- 参数计算（geqo_main.cpp:84-85, 274-311）：`pool_size = gimme_pool_size(number_of_rels)`；当 `Geqo_pool_size >= 2` 时直接采用配置值，否则按 `size = pow(2.0, nr_rel + 1.0)` 计算，先与 `maxsize = 50 * Geqo_effort` 比较（超过则取上限），再与 `minsize = 10 * Geqo_effort` 比较（不足则取下限），最后 `(int)ceil(size)`；`number_generations = gimme_number_generations(pool_size)`，`Geqo_generations > 0` 时采用配置值，否则等于 pool_size。两处意味着 `Geqo_pool_size` 为 0 或 1 都被当作"自动"，默认 effort=5 时池大小落在 [50, 250]。
- 初始化与排序（:87-99）：`alloc_pool(root, pool_size, number_of_rels)`、`random_init_pool(root, pool)`、`sort_pool(root, pool)`；排序注释说明只排一次，因为此后 kid 只替换池中最差个体（替换语义由 geqo_pool.cpp:spread_chromo 提供，本 attempt 未重读该文件，来自已审 claim 与源码注释）。GEQO_DEBUG 下打印 `pool_size`、`pool->data[0].worth`、`pool->data[pool_size-1].worth`，可见排序把最优放在下标 0、最差放在末尾。
- 双亲与交叉缓冲分配（:101-152）：`momma`、`daddy` 均由 `alloc_chromo(root, pool->string_length)` 分配；随后按宏组分配：ERX 分配 `edge_table = alloc_edge_table(...)`；PMX 只分配 `kid = alloc_chromo(...)`；CX/PX/OX1/OX2 分配 `kid` 与 `city_table = alloc_city_table(...)`；CX 另有 `cycle_diffs`、`mutations` 计数。
- 主循环（:154-199）：`for (generation = 0; generation < number_generations; generation++)`：先 `geqo_selection(root, momma, daddy, pool, u_sess->attr.attr_sql.Geqo_selection_bias)`（每代把池中按 bias 选出的两个个体复制进 momma/daddy）；再按宏执行交叉：ERX 用 `gimme_edge_table` 建边表、把 `kid = momma` 后 `gimme_tour` 直接把子串写回 `kid->string` 并累计 `edge_failures`；PMX 调 `pmx`；CX 调 `cx` 并在 `cycle_diffs == 0` 时 `mutations++` 且 `geqo_mutation`；PX/OX1/OX2 分别调 `px`/`ox1`/`ox2`。交叉后 `kid->worth = geqo_eval(root, kid->string, pool->string_length)`，再 `spread_chromo(root, kid, pool)`；GEQO_DEBUG 下每 `status_interval = 10` 代调用 `print_gen`。
- 收尾（:201-265）：GEQO_DEBUG 汇总 edge_failures/mutations 并打印池与最优值；`best_tour = (Gene*)pool->data[0].string`；`best_rel = gimme_tree(root, best_tour, pool->string_length)`；随后 `free_chromo(momma)`、`free_chromo(daddy)`，按宏 `free_edge_table`（ERX）或 `free_chromo(kid)`（+`free_city_table`），再 `free_pool`，最后 `root->join_search_private = NULL` 并返回 best_rel。

## 状态和消费者
- Pool：`size = pool_size`、每条染色体 `string_length = number_of_rels` 个基因；worth 由 geqo_eval 填入，按 worth 升序（最优在 data[0]）。
- momma/daddy：每代被 geqo_selection 覆盖；ERX 分支把 kid 指向 momma 并就地改写其 string，因此 momma 的内容在交叉后不再代表池中选择出的亲本，但下一代 selection 会重新复制，属于有意复用。非 ERX 分支 kid 是独立染色体，整个循环复用同一对象。
- 局部状态：ERX 的 edge_table/edge_failures、CX 的 cycle_diffs/mutations、GEQO_DEBUG 的 status_interval 都只在本次 geqo() 调用内有效。
- best_tour 指向池内数据，必须在 free_pool 之前被 gimme_tree 消费；best_rel 的 RelOptInfo 在 planner 上下文创建（最后一次 gimme_tree 不经过 geqo_eval 的 GEQO 子上下文），因此可以在 geqo() 返回后继续被 planner 使用。
- 消费者：make_rel_from_joinlist 消费返回的 best_rel（入口条件见已审 claim join-search-entry-selection）；随机状态 random_state 被 geqo_rand/erand48 消费（已审 claim 覆盖 geqo_random.cpp）；Geqo_selection_bias 被每代 geqo_selection 消费；Geqo_seed 由 geqo_set_seed 消费；Geqo_pool_size/Geqo_effort/Geqo_generations 由本文件两个 helper 消费；同一批 GUC 另由 globalplancache_util.cpp 写入计划缓存环境（已审 claim，本 attempt 未重读）。

## 开发与 review
- 四处宏组（声明、分配、每代交叉、释放）必须同步改动：只改一处会出现 edge_table 未分配却走 ERX、或 kid/city_table 未初始化就走 PMX/CX/PX/OX1/OX2、或释放与分配不匹配。
- ERX 下 kid 是 momma 的别名：清理段不能 `free_chromo(kid)`，否则重复释放；任何在 `spread_chroma` 之后继续使用 momma 的改动都要先确认 selection 已重新填充。
- 必须保持：最后一次 gimme_tree 在 free_pool 之前；所有正常返回路径都在返回前清空 root->join_search_private（priv 是栈对象）；不得在循环内新增可能 longjmp 的路径而不考虑释放（当前异常路径依赖语句上下文统一回收）。
- 修改 pool_size 公式要保持 "配置值 < 2 视为自动" 与上下限 `10*effort..50*effort` 语义；修改 generations 要保持 0 表示取 pool_size；两者与 GUC 注册说明（已审 claim）必须一致。
- 修改排序或替换逻辑会破坏"只排一次"的前提；若更换交叉算子，要同时处理 CX 特有 mutation 行为，避免其他算子悄悄失去变异步骤。
- review 检查点：宏组四处一致性、别名释放、清理顺序、join_search_private 置空、GEQO_DEBUG 分支只做诊断不改状态。

## 测试与未知
- 可由源码推导的预期：Geqo_pool_size=0/1 时 pool_size = clamp(2^(n+1), [10*effort, 50*effort]) 并向上取整；Geqo_generations=0 时代数等于 pool_size；循环恰好执行 number_generations 次，每次一次 geqo_eval；best 个体取池下标 0；geqo() 正常返回后 root->join_search_private == NULL。
- 边界/反例：pool_size=1 被忽略；generations=0 不是零代；ERX 下 kid 与 momma 同对象；非 ERX 下 kid 每代复用；GEQO_DEBUG 未定义时 debug 日志/print 不编译，缺日志不能证明未走 GEQO；若调用方传入的 initial_rels 长度与 number_of_rels 不一致，本文件不做校验（genes 由 1..number_of_rels 生成，见 gimme_tree 侧）。
- 未运行：source_only，未执行 SQL、GUC 设置、编译或故障注入；random_init_pool 是否逐染色体调用 geqo_eval、sort_pool 比较方向、spread_chroma 替换规则来自已审 claim/源码注释，本 attempt 未重读 geqo_pool.cpp；实际 TU 是否定义 GEQO_DEBUG/交叉宏未由编译器绑定验证。
