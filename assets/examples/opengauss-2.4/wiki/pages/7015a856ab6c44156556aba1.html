## 行为和入口
- 入口与前置：`RelOptInfo* gimme_tree(PlannerInfo* root, Gene* tour, int num_gene)` 定义在 geqo_eval.cpp（本租约读取的 1-200 区间后段）；首先 `GeqoPrivateData* priv = (GeqoPrivateData*)root->join_search_private;`，因此必须在 geqo() 已设置 join_search_private 的前提下调用（geqo_eval.cpp 的 geqo_eval 与 geqo_main.cpp:230 的最终调用都满足）；本函数不检查 priv 为 NULL。
- 增量构造（gimme_tree 主体）：`clumps = NIL`；对 `rel_count = 0 .. num_gene-1`：`cur_rel_index = (int)tour[rel_count]`；`cur_rel = (RelOptInfo*)list_nth(priv->initial_rels, cur_rel_index - 1)`；`palloc(sizeof(Clump))` 得到 `cur_clump`，`joinrel = cur_rel`、`size = 1`；`clumps = merge_clump(root, clumps, cur_clump, false)`。基因是 1-based，且本函数不校验 cur_rel_index 的范围或 tour 是否为排列。
- 强制收尾：`if (list_length(clumps) > 1)` 时新建 `fclumps = NIL`，按现有 clumps 顺序 `foreach`，对每个 clump 依次 `fclumps = merge_clump(root, fclumps, clump, true)`，最后 `clumps = fclumps`。
- 失败出口：`if (list_length(clumps) != 1) ereport(ERROR, (errmodule(MOD_OPT), errcode(ERRCODE_OPTIMIZER_INCONSISTENT_STATE), errmsg("failed to join all relations together")));`；成功则 `return ((Clump*)linitial(clumps))->joinrel;`。
- 头部注释说明设计动机：旧实现只按给定顺序左连接，无法产生 bushy plan，在存在连接顺序限制时可能无合法计划；现实现把 tour 当指导，推迟非法或不合适的连接，必要时生成 bushy plan。

## 状态和消费者
- Clump：`{RelOptInfo* joinrel; int size;}`（geqo_eval.cpp 顶部 typedef）。列表 ordering 约定为"大 clump 在前"；size=1 的新 clump 通常追加在末尾。
- merge_clump（geqo_eval.cpp 201-296 前半）：`foreach (lc, clumps)` 逐个尝试：条件为 `force || desirable_join(root, old_clump->joinrel, new_clump->joinrel)`；满足则 `joinrel = make_join_rel(root, old_clump->joinrel, new_clump->joinrel)`；`make_join_rel` 返回非 NULL 时：`set_cheapest(joinrel)`、把新 clump 吸收进旧 clump（`old_clump->joinrel = joinrel`、`old_clump->size += new_clump->size`、`pfree_ext(new_clump)`）、`list_delete_cell(clumps, lc, prev)` 删除旧 clump，然后递归 `merge_clump(root, clumps, old_clump, force)`；返回 NULL 时继续尝试下一个 clump（连接顺序不合法）。没有可合并对象时按大小插入：clumps 为空或 `new_clump->size == 1` 直接 `lappend`；大于首元素 size 则 `lcons`；否则沿链找到第一个 size 小于它的位置后 `lappend_cell(clumps, lc, new_clump)`。
- desirable_join：`have_relevant_joinclause(root, outer_rel, inner_rel) || have_join_order_restriction(root, outer_rel, inner_rel)` 为真才返回 true，否则推迟连接（非 force 阶段不产生笛卡尔积）。
- 状态生产与消费：make_join_rel 向 root->join_rel_list 追加连接关系并（按注释）依赖其尚不存在；set_cheapest 填充 joinrel->cheapest_total_path，供 geqo_eval 读取 fitness 和最终 best_rel 使用。本函数自身不写 join_rel_list/hash/level，也不切换内存上下文。
- 跨模块影响：make_join_rel、set_cheapest、have_relevant_joinclause、have_join_order_restriction 均属 optimizer/path 的接口（本 attempt 未读其实现）；gimme_tree 的启发式决定最终计划形态与 GEQO fitness，但不改变 geqo() 对外的 best_rel 类型。

## 开发与 review
- 保持 clump 列表 ordering 约定（大在前）：新 clump 插入位置与强制合并顺序都隐式依赖它；破坏排序会改变哪一对先尝试、进而改变生成的 bushy 形态与 fitness。
- 吸收时先 `pfree_ext(new_clump)` 再删除旧 clump，两级递归都以 old_clump 为携带者：不得在递归前使用已释放的 new_clump；Clump 只是包装，joinrel 由 planner 上下文/GEQO 子上下文管理，不要 pfree joinrel。
- desirable_join 只决定"何时可以合并"，真正的合法性仍由 make_join_rel 返回 NULL 把关；force=true 也只放宽启发式，不放宽语义限制。因此"强制合并"不等于保证成功，失败由最终 ereport 表达。
- gimme_tree 依赖调用方契约：join_search_private 有效、tour 是 1..num_gene 的排列、initial_rels 长度 >= num_gene、join_rel_level 为 NULL；任何新增校验应放在入口而非循环内，避免改变正常路径行为。
- 修改失败出口时保留 errmodule(MOD_OPT) 与 ERRCODE_OPTIMIZER_INCONSISTENT_STATE，便于上层识别规划器不一致；不要改成静默返回部分连接，geqo_eval 的 fitness 读取会崩溃。
- review 检查点：clump 排序、递归终止（每次吸收 size 增大、clump 数减少）、make_join_rel NULL 的继续搜索、pfree/new_clump 生命周期、单 clump 返回前是否已 set_cheapest。

## 测试与未知
- 可由源码推导的预期：两表合法连接时 tour 结束后只有一个 clump，不触发强制阶段；无连接条件的两表在非 force 阶段不合并，tour 结束后由 force 阶段合并（make_join_rel 对笛卡尔积是否合法由 path 层决定，本 attempt 未读）；若 force 阶段所有尝试都返回 NULL，最终 clump 数 != 1 并报 "failed to join all relations together"。
- 结构预期：size=1 的基表总被追加（lappend），更大的 clump 按 size 降序插入；被吸收的 Clump 结构被 pfree_ext，joinrel 保留；返回的 joinrel 是唯一 clump 的 joinrel 且已 set_cheapest。
- 边界/反例：tour 中出现重复基因或超出 initial_rels 长度的索引时，本函数无防御（list_nth 越界属未定义）；num_gene==1 时直接返回该基表 RelOptInfo（不调用 make_join_rel/set_cheapest），但 geqo() 入口要求 levels_needed>1；较老注释所述"总是左连接"的行为已不成立。
- 未运行：source_only，未执行 SQL、EXPLAIN、编译或故障注入；make_join_rel/set_cheapest/have_relevant_joinclause/have_join_order_restriction 的实现与本函数的实际计划形态未验证；"笛卡尔积在 force 阶段总能成功"未证实，保留 unknown。
