# make_rel_from_joinlist 仅在 enable_geqo 打开且 levels_needed >= geqo_threshold 时才调用 geqo()

## 行为和入口
server/src/gausskernel/optimizer/path/allpaths.cpp 的 make_rel_from_joinlist 以 levels_needed = list_length(joinlist) 计算参与连接的分项数。levels_needed <= 0 直接返回 NULL；levels_needed == 1 直接返回唯一的 initial_rels 元素，不进入任何连接搜索算法。只有 levels_needed > 1 时，函数先把 initial_rels 挂到 root->initial_rels（注释说明 has_legal_joinclause() 需要看它），再执行选择分支：allpaths.cpp:3400 条件为 `u_sess->attr.attr_sql.enable_geqo && levels_needed >= u_sess->attr.attr_sql.geqo_threshold`；条件成立时 allpaths.cpp:3401 返回 geqo(root, levels_needed, initial_rels)，否则 allpaths.cpp:3403 返回 standard_join_search(root, levels_needed, initial_rels)。

## 状态和消费者
选择结果直接决定后续 join 搜索实现：geqo() 定义于 server/src/gausskernel/optimizer/geqo/geqo_main.cpp:48；动态规划路径是同一文件的 standard_join_search。两个函数都消费 allpaths 预先写入的 root->initial_rels：geqo() 把它存入私有 GeqoPrivateData.initial_rels，gimme_tree() 再按 tour 索引取出。开关与阈值分别来自 u_sess->attr.attr_sql.enable_geqo 和 geqo_threshold，二者是 PGC_USERSET 会话级 GUC（见 GUC 注册 claim），因此同一 SQL 在不同会话配置下可走不同搜索算法。

## 开发与 review
修改该分支时必须保持：levels_needed 仍是 list_length(joinlist)；root->initial_rels 在进入任一算法前已赋值；阈值比较使用 >=（等于 geqo_threshold 即启用 GEQO）。若增加新的连接搜索插件或旁路入口，需要说明它与 geqo()/standard_join_search 的互斥关系以及对 root->initial_rels 的所有权。

## 测试与未知
可据源码推导的边界：levels_needed == 1 时两种算法都不调用；levels_needed 在 [2, geqo_threshold-1] 或 enable_geqo=false 时走 standard_join_search；levels_needed >= geqo_threshold 且 enable_geqo=true 时走 geqo()。本轮未运行任何 SQL 或回归测试，运行时行为未验证。其他模块是否存在 geqo() 的间接调用/重载、以及插件 hook 是否会替换 join search，未在本租约证据中确认。
