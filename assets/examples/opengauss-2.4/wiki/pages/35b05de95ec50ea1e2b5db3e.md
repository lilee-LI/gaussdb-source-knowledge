## 行为和入口
geqo()（server/src/gausskernel/optimizer/geqo/geqo_main.cpp:48）在开头把局部变量 priv 的地址赋给 root->join_search_private，并把入参 initial_rels 存入 priv.initial_rels，随后 geqo_set_seed(root, u_sess->attr.attr_sql.Geqo_seed)；函数末尾在释放 momma/daddy/edge_table/pool 之后执行 root->join_search_private = NULL 再返回 best_rel。gimme_tree() 从 root->join_search_private 取回 GeqoPrivateData 并据此索引 initial_rels（geqo_eval.cpp 读取区间内可见）。

geqo_eval()（geqo_eval.cpp）对被调用方 gimme_tree() 的 planner 状态做了成对保护：savelength = list_length(root->join_rel_list)，savehash = root->join_rel_hash，AssertEreport(root->join_rel_level == NULL)；随后 root->join_rel_hash = NULL，调用 gimme_tree()，再执行 root->join_rel_list = list_truncate(root->join_rel_list, savelength) 和 root->join_rel_hash = savehash。它创建名为 "GEQO" 的 AllocSet 内存上下文作为 CurrentMemoryContext 的子上下文，所有 gimme_tree 内部临时分配都在其中；正常路径切换回 oldcxt 后 MemoryContextDelete(mycontext)。

## 状态和消费者
跨模块状态影响有两类。第一，geqo 模块临时改写 path 模块拥有的 PlannerInfo 字段：join_rel_list 只允许在尾部追加（源码注释假设新增项 append 在末尾），join_rel_hash 被临时置空以便局部重建，join_rel_level 被断言为 NULL 且没有恢复语句；geqo() 还把 join_search_private 当作 GEQO 私有槽位，正常退出后清空。第二，全局计划缓存（server/src/gausskernel/process/globalplancache/globalplancache_util.cpp）的 GlobalPlanCache::FillEnvSignatures 把 enable_geqo 写入 env_signature2 第 0 位（文件第 106 行），EnvFill 把 geqo_threshold、Geqo_effort、Geqo_pool_size、Geqo_generations、Geqo_selection_bias、Geqo_seed 复制进 GPCEnv（第 158-163 行）。因此这些 GUC 的取值属于计划缓存环境身份的一部分，不同取值对应的缓存计划不应视为同一环境。

## 开发与 review
修改 geqo_eval 的状态保护时必须维持：保存/恢复围绕单次 gimme_tree 成对出现；join_rel_list 的新增项只能 append；不得在 gimme_tree 内给 join_rel_level 赋值（否则断言失败且无恢复逻辑）；GEQO 上下文必须保持为 planner 上下文的子上下文，使 ereport(ERROR) 中止时仍能随上层上下文释放。修改 geqo() 时必须保证所有正常返回路径都清空 root->join_search_private，避免悬挂指向栈变量的指针。修改 GUC 集合时必须同步 globalplancache_util.cpp 的签名/字段，否则计划缓存会错误复用跨配置的计划。

## 测试与未知
可推导的测试预期：同一条多表查询在 enable_geqo=false/true 或不同 geqo_threshold 下应产生不同的计划缓存环境标识；geqo_eval 返回后 root->join_rel_list 长度应等于进入前长度、join_rel_hash 指针应等于进入前值。反例/边界：源码只在 AssertEreport 中断言 join_rel_level == NULL，非断言构建是否检查未验证；gimme_tree 通过 ereport(ERROR) 失败时恢复语句不执行，源码注释称子内存上下文会随中止释放，但 join_rel_hash/join_rel_list 的恢复在该路径未发生（查询已中止，root 生命周期结束），本轮未运行任何故障注入或 SQL。geqo_eval.cpp 第 201-296 行（merge_clump/desirable_join 等）本租约未读，未纳入本 claim。
