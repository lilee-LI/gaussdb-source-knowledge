# gimme_tree clump 合并、desirable_join 推迟与强制合并失败出口的测试预期

审阅状态 independent_review

## 测试目标
为 gimme_tree/merge_clump/desirable_join 建立源码推导的结构性预期，覆盖：增量合并、按 size 排序、tour 结束后的强制合并、以及最终 clump 数不为 1 时的 ereport 出口。本义务不运行 SQL、EXPLAIN、编译或故障注入，execution_status=not_run。

## 预期分支（依据 geqo_eval.cpp 的 gimme_tree/merge_clump/desirable_join 源码与本任务 claim）
- 两表且存在相关连接条件：非 force 阶段 desirable_join 为真，merge_clump 经 make_join_rel 合并为单 clump，tour 结束不进入强制阶段，返回已 set_cheapest 的 joinrel。
- 两表无连接条件（笛卡尔积）：desirable_join 为假（have_relevant_joinclause 与 have_join_order_restriction 均不成立），非 force 阶段产生两个 clump；tour 结束后进入强制阶段，由 make_join_rel 是否接受该连接决定能否合并。若 make_join_rel 返回非 NULL 则形成单 clump 正常返回。
- 三表且首对不可连接：第一、二个基因各成 clump（列表按 size 均为 1，追加顺序）；第三个基因按 tour 顺序尝试合并，最终或经强制阶段收敛为单 clump。
- 强制阶段仍无法合并：clump 数保持 >1，gimme_tree 以 ereport(ERROR)（errmodule MOD_OPT，errcode ERRCODE_OPTIMIZER_INCONSISTENT_STATE，errmsg "failed to join all relations together"）失败退出，不返回部分连接。
- num_gene==1：直接返回该基表的 RelOptInfo，不调用 make_join_rel/set_cheapest；该分支只能由绕过 geqo() 入口的调用触发（geqo() 要求 levels_needed>1）。

## 结构预期与反例
- 列表 ordering：size=1 的新 clump 总被 lappend 到末尾；size>1 的 clump 必须按 size 降序插入（大于首元素用 lcons）。若观察到更大 clump 排在更小 clump 之后，即违反 merge_clump 的插入规则。
- 被吸收的 Clump 结构由 pfree_ext 释放、joinrel 保留；size 累加到旧 clump。
- make_join_rel 返回 NULL 不是立即插入 clump，而是继续尝试下一个旧 clump。
- tour 中出现重复或越界基因时本函数不做防御（list_nth 越界属未定义行为），不应把此类输入当作支持的测试用例。

## 未运行与未知
- 未执行任何 SQL/EXPLAIN；无法确认具体查询会走到哪条 clump 分支，也无法确认 make_join_rel 对笛卡尔积/连接顺序限制的实际返回值。
- have_relevant_joinclause/have_join_order_restriction/make_join_rel 属 optimizer/path，本 attempt 未读其实现；上述分支以 gimme_tree 内部调用与返回值为准。
- GEQO 是否被执行取决于入口条件（enable_geqo/geqo_threshold/levels_needed），测试需先用已审 claim join-search-entry-selection 的前置条件确认。
