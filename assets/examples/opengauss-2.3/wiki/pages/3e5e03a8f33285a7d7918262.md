# 机制：池升序不变量与 spread_chromo 右移替换

openGauss · content-addressed · linux-native

审阅状态 依赖已变化，待复核

机制：池的有序不变量是“下标越小 worth 越小”，即 data[0] 最优、data[size-1] 最差。它依赖两个前提：sort_pool 初始化时已按 compare 升序排好；每代只插入一个 kid 而池大小不变。spread_chromo 先做早退：若 chromo->worth 严格大于当前最差（>），直接丢弃；相等则继续。然后用 top/mid/bot 二分找 index（相等时可能落在 mid 或 bot）。随后 geqo_copy 把 kid 的 string_length 个 gene 逐基因复制到最后一个槽位 pool->data[size-1] 的既有缓冲区，并把该槽位的 worth 改为 kid 的 worth（string 指针不变、内容被覆盖）。接着 swap_chromo 保存的正是这个已更新的槽位（同一分配缓冲区、kid 的 worth），而不是旧最差；循环 i=index..size-1 依次把当前槽的 string 指针与 worth 存入 tmp，将 swap 写入该槽，再把 tmp 作为下一轮 swap：结果 index 处得到 kid（复用原最差缓冲区），index+1..size-1 依次放入原 data[index..size-2]，原最差条目的旧 worth 已被 kid 覆盖而丢失。结果是非降序保持；但“只拒绝严格更差”意味着与最差相等的 kid 会进入移位并可能把另一个等值个体挤出。

## 适用条件

- pool->size 在循环中不变
- worth 为有限值且 compare 能给出符号

## 边界与反例

- 若 worth 为 NaN，比较与减法都不成立，有序不变量无法保证
- kid 严格等于最差时不会被早退，会参与替换
- 不能把 swap_chromo 说成保存旧最差的 worth：它在 geqo_copy 之后读取，已是 kid 的 worth，且复用同一 string 缓冲区
