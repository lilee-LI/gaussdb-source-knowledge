# join.sql 与 single_node_join.sql 已包含多重退化 IN 的 GEQO 存量回归脚本

openGauss · content-addressed · linux-native

审阅状态 依赖已变化，待复核

在冻结快照 snapshot:362bacfe9f24395fe92a540a2a35e0dd 中，server/src/test/regress/sql/join.sql 第 375-393 行与 server/src/test/regress/sql/single_node_join.sql 第 336-354 行都包含同一类既有回归用例：先执行一条针对 tenk1 的多重退化 IN 子查询 count(*) 语句，随后以注释“try that with GEQO too”引出同一查询的 GEQO 版本。join.sql 使用显式事务 start transaction，single_node_join.sql 使用 begin；两者都在事务内执行 set geqo = on 与 set geqo_threshold = 2，执行查询后以 rollback 回滚设置与事务。server/src/test/regress/expected/single_node_join.out 第 2145-2170 行记录了对应的存量预期文本：普通查询与 GEQO 查询各出现一次 count=1 及“(1 row)”，并保留 begin、set、rollback 文本。该 count=1 只是 expected 文件中的既有预期文本，不能据此证明当前运行成功，也不能证明查询在实际执行时确实走了 GEQO 路径。本观察仅说明既有测试脚本与预期文本存在，不宣称仓库中没有其他 GEQO 测试，也不构成已批准的产品行为或人工专家验收。

## 适用条件

- 仅在同一冻结快照 snapshot:362bacfe9f24395fe92a540a2a35e0dd 的上述源码区间内成立。
- join.sql 的 GEQO 分支以 start transaction 开启显式事务并在末尾 rollback；single_node_join.sql 以 begin 开启并在末尾 rollback。
- expected/single_node_join.out 中的 count=1 被理解为存量预期文本，而非运行回执或 GEQO 实际路径的证明。
- 结论限于“存在 GEQO 相关存量回归用例”，不扩展为测试已执行、通过或覆盖全部 GEQO 场景。

## 边界与反例

- 若在冻结快照的 join.sql 或 single_node_join.sql 对应区间没有出现 geqo = on 与 geqo_threshold = 2 的设置及同一查询，则该观察不成立。
- 若把 expected 文件中的 count=1 直接当作当前运行成功或实际使用 GEQO 的证据，则与“仅为存量预期文本”的事实冲突。
- 若据本观察断言仓库中不存在其他 GEQO 测试，则超出证据范围，不成立。
