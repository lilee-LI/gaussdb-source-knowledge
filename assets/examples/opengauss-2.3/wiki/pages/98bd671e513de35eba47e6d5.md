# claim：备用交叉算子编译但不可达

openGauss · content-addressed · linux-native

审阅状态 依赖已变化，待复核

claim：PMX/CX/PX/OX1/OX2 与 geqo_mutation 在本快照被编译但没有运行可达性。证据有两面：构建面，CMake 的 AUX_SOURCE_DIRECTORY 与 Makefile 的 15 个 OBJ 都包含这些 .cpp；控制流面，geqo_main.cpp 用 #if defined(ERX)/#elif defined(PMX)... 分派，而 geqo.h 已无条件 #define ERX，所以 #elif 分支与 CX 下的 geqo_mutation 调用都不会被选中。结论只能到“源码算法存在、当前源码不可达”；不能对不可达算子给出运行时行为或性能断言。边界：单独定义 PMX 不会改变分派；要启用已有变体，必须去掉 geqo.h 的 #define ERX、在包含 geqo.h 之后 #undef ERX，或调整 main 的分派顺序；随后 main 中对应 #elif 分支自带的 alloc_chromo(kid)/free_chromo(kid) 与 city table 生命周期会自动进入编译，需核对现有分支并重验算法，不必也不应声称要另改 main 的 alloc/free。只有新增变体或改变所有权才需要改代码。

## 适用条件

- 当前源码仅 ERX 活跃
- Makefile 15 OBJ = CMake 全部 .cpp
- 启用已有变体时 main 中对应 #elif 分支已自带 alloc/free，无需新增

## 边界与反例

- 单独 -DPMX 不改变分派；只有去掉/undef ERX 或调整分派后，pmx 分支及其已有 alloc/free 路径才可能可达
- 启用已有变体不应被描述成必须改 main 的 alloc/free；新增变体或改变所有权才需要改代码
