决策：开发修改指南与 Review 检查点

openGauss · content-addressed · linux-native · 依赖已变化，待复核

开发修改指南：改池/选择/替换时，先确认 pool->size>=2、池非降序、spread_chromo 只拒绝严格更差，否则会破坏 selection 去重与最差替换；改交叉时，记住 ERX 下 kid==momma；若要启用已有 PMX/CX/PX/OX1/OX2，只需处理 geqo.h 的 ERX 宏（去掉/undef）或调整 main 分派，main 中对应 #elif 分支已自带 alloc_chromo(kid)、free_chromo(kid) 与 city table 释放，会自动选中；不要声称必须改 main 的 alloc/free，也不要声称只改宏必泄漏。启用已有变体仍须核对现有分支并重验未验证算法；只有新增变体或改变所有权才需要改代码。改评估时，保持 GEQO 临时上下文是 planner 上下文子节点、join_rel_list 追加在尾、hash 置空再还原、join_rel_level==NULL 的 AssertEreport 检查（不保存/恢复，失败会 ERROR/依构建 Assert），并记住 ERROR 路径没有正常返回的状态恢复保证；fitness 仍取 cheapest_total_path 首 Path。改 gimme_tree 时，别让 force 绕过 make_join_rel，保留“最终 clump!=1 即报错”；改 GUC 时，同时更新 geqo.h 常量、guc_sql.cpp 默认/范围与 knl 会话字段，且 bias 不得低于 1.5、pool_size=1 仍应忽略、seed 不承诺跨架构一致；新增文件时，Makefile OBJS 要同步（CMake 自动收集），GEQO_DEBUG 默认不定义。

Review 检查点：E1 门控是否 enable_geqo && levels_needed>=geqo_threshold；E2 7 参数默认/范围是否两处一致；E3 pool_size=1 是否仍被忽略；E4 spread 是否只拒绝严格更差且右移后仍非降序；E5 选择在 size>1 时是否只保证槽位下标去重（不要求内容不同）；E6 ERX 释放路径是否不 free(kid)，启用已有变体时对应 #elif 是否已有 free_chromo(kid)；E7 geqo_eval 是否截断 list/还原 hash/删临时上下文，并是否正确描述 join_rel_level 的 AssertEreport 与 ERROR 边界；E8 gimme_tree 是否仍以 make_join_rel 非 NULL 为合法性条件且 clump!=1 报错；E9 新变体/新文件是否两条构建路径都同步；E10 调试宏是否未被意外引入生产构建。

适用条件

  • 修改限于 GEQO 子目录及其头文件
  • 任何跨模块接口变更需重新核对 make_join_rel/set_cheapest 契约

边界与反例

  • 若新增变体或改变所有权却不改 main 的 alloc/free，才会产生泄漏或双重释放；启用已有变体不应被描述成这种情形
  • 只改 guc_sql.cpp 不改 geqo.h 常量，会让默认值不一致
  • 把 join_rel_level 当成会被保存/恢复，或要求 ERROR 后同一 PlannerInfo 继续复用，会误判 geqo_eval 的错误边界
