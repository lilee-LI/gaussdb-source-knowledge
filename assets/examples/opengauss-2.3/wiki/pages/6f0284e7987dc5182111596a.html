契约：geqo → geqo_eval 的候选打分

返回知识目录

openGauss · content-addressed · linux-native · 依赖已变化，待复核

契约：geqo 每次需要给 kid 打分时调用 geqo_eval；在调用者满足前置（tour 是 1..num_gene 的有效排列、priv->initial_rels 至少 num_gene 项且与 tour 对应）时，geqo_eval 返回 gimme_tree 形成的唯一 joinrel 的 cheapest_total_path 首 Path 的 total_cost，并在正常返回前把 join_rel_list 截回原长度、把 join_rel_hash 还原。join_rel_level 只用 AssertEreport 检查是否为 NULL，不保存也不恢复；条件失败时宏先 Assert，再 ereport(ERROR, ERRORCODE_ASSERT_FAILED)（Assert 的具体反应依构建）。因此 ERROR 路径没有正常返回的状态恢复保证，不能要求 ERROR 后同一 PlannerInfo 继续复用。返回值的有限/可比较性不是无条件保证，而是算法适用前提：它取决于 make_join_rel/set_cheapest 产出的路径成本，必须有限、非 NaN 才能参与 sort_pool/spread_chromo 的大小比较。生产者必须先把 initial_rels 放进 GeqoPrivateData。

适用条件

  • num_gene == number_of_rels == pool->string_length
  • tour 每个元素在 1..num_gene 且构成排列（无重复、无越界）
  • 返回的 total_cost 有限、非 NaN 才能参与后续比较
  • join_rel_level 只被检查为 NULL，不被保存/恢复

边界与反例

  • tour 越界（gene<1 或 >num_gene）会让 gimme_tree 的 list_nth(initial_rels, gene-1) 使用非法索引
  • 重复但仍在 1..num_gene 的 gene 索引本身合法，但破坏“1..num_gene 排列/关系不重复”的前置，合并不变量不受契约保证
  • 上述非法输入均不保证统一报 ERROR；不能把越界当作必然 ERROR
  • 若成本为 NaN/无穷，compare 与 spread 的有序假设不成立
  • ERROR 路径不保证 join_rel_list/join_rel_hash 已还原，不能要求同一 PlannerInfo 继续复用

前提

  • root->join_search_private 指向 GeqoPrivateData
  • priv->initial_rels 已设置且至少 num_gene 项
  • tour 长度为 num_gene，元素在 1..num_gene 且无重复（有效排列）

保证

  • 正常返回且 joinrel 产出有限成本时，返回 cheapest_total_path 首 Path 的 total_cost
  • 正常返回时 join_rel_list 截回原长度
  • 正常返回时 join_rel_hash 还原
  • 正常返回时 GEQO 临时上下文被删除
  • join_rel_level 不做保存/恢复

不变量

  • 调用期间 root->join_rel_level 必须为 NULL；geqo_eval 用 AssertEreport 检查，不保存/恢复，失败时先 Assert 再 ereport(ERROR, ERRORCODE_ASSERT_FAILED)（Assert 反应依构建）
  • 新增 join_rel_list 条目必须追加在尾部
  • 正常返回才保证 join_rel_list/hash 还原；ERROR 路径不保证
  • 返回后不保留任何 joinrel 指针
  • 返回值有限/可比较性为算法适用前提，不是无条件保证
