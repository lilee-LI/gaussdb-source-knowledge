# L4 特性：候选适应度与临时上下文

openGauss · content-addressed · linux-native

审阅状态 依赖已变化，待复核

L4 特性：适应度评估与临时内存。每个候选 tour 调 geqo_eval 得到 total_cost；评估内部用独立 GEQO 上下文隔离 gimme_tree 产生的所有临时 RelOptInfo/Path/Clump，并在正常返回前把 root->join_rel_list 截回原长度、把 join_rel_hash 还原；join_rel_level 只用 AssertEreport 检查为 NULL，不保存也不恢复（失败时宏先 Assert，再 ereport(ERROR, ERRORCODE_ASSERT_FAILED)，Assert 的具体反应依构建）。因此 ERROR 路径没有正常返回的状态恢复保证。fitness 只取 cheapest_total_path 链表的第一个 Path 的 total_cost，因此“候选好坏”取决于该连接顺序下优化器选出的最便宜总路径，而不是每个子连接的开销和；该成本的有限/可比较性是算法适用前提，不是无条件保证。

## 适用条件

- gimme_tree 新增的 join_rel_list 条目必须追加在尾部
- join_rel_hash 以整指针替换方式隔离
- join_rel_level 只被检查为 NULL，不被保存/恢复

## 边界与反例

- 若 join_rel_list 已有条目且新条目被插入中部，list_truncate 会误删或遗留
- 若 cheapest_total_path 首 Path 成本为 NaN/无穷，后续 compare/spread 的有序假设不成立
- 若 join_rel_level 非 NULL，AssertEreport 会 Assert 并 ereport(ERROR, ERRORCODE_ASSERT_FAILED)；不能要求 ERROR 后同一 PlannerInfo 继续复用
