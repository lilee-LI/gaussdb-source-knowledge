# 机制：GEQO GUC 注册、读取时机与消费者

openGauss · content-addressed · linux-native

审阅状态 依赖已变化，待复核

机制：7 个 GEQO 参数均为 PGC_USERSET、NODE_ALL、分组 QUERY_TUNING_GEQO，可在会话级 SET；源码只证明这些消费点在实际执行到的规划入口/GEQO 调用中读取，不证明每条后续 SQL 一定重新规划，也不证明已有缓存计划一定失效。GUC 来源覆盖、事务局部恢复（如 SET LOCAL）、SHOW/pg_settings 实现与计划缓存失效本次未研究，属未知边界。没有 SIGHUP/POSTMASTER 级 GEQO 参数。读点分布：enable_geqo 与 geqo_threshold 在 allpaths.cpp 的 make_rel_from_joinlist 判断；Geqo_seed 在 geqo() 开始处一次性写入 erand48 状态；Geqo_effort/Geqo_pool_size 在 gimme_pool_size；Geqo_generations 在 gimme_number_generations；Geqo_selection_bias 每代传给 geqo_selection。优先级：显式 Geqo_pool_size>=2 覆盖 effort 推导，Geqo_generations>0 覆盖 pool_size 默认；Geqo_pool_size=1 被静默忽略。

## 适用条件

- 所有参数注册默认与 geqo.h 常量一致
- 读点在实际执行到的规划入口/GEQO 调用中；具体规划与缓存复用策略未研究
- 未研究 GUC 来源覆盖、事务局部恢复、SHOW/pg_settings 实现与计划缓存失效

## 边界与反例

- 不能声称 SET 对已开始的规划生效；读点在各阶段入口
- 不能声称 SET 必然触发后续 SQL 重新规划或使已有缓存计划失效——本次未研究计划缓存失效
- 不能声称 bias 可取 1.0；注册范围下限 1.5
