# GEQO 子模块总览：遗传式连接顺序搜索

openGauss · content-addressed · linux-native

审阅状态 依赖已变化，待复核

GEQO 是 openGauss 优化器中以遗传算法近似求解连接顺序的子系统，位于 server/src/gausskernel/optimizer/geqo，接口头在 server/src/include/optimizer。本快照已核对的调用入口是 allpaths.cpp 的 make_rel_from_joinlist：在 levels_needed>1 且 enable_geqo 为真、levels_needed>=geqo_threshold 时调用 geqo(root, levels_needed, initial_rels)，否则走 standard_join_search。本快照只核对了该入口，不把局部检索包装成全仓唯一性证明。

算法骨架：geqo() 先把 initial_rels 和随机状态放进栈上 GeqoPrivateData，并挂到 root->join_search_private；用 Geqo_seed 初始化 erand48 状态；按 Geqo_effort/Geqo_pool_size/Geqo_generations 决定池大小与代数；alloc_pool 后 random_init_pool 逐个 init_tour+geqo_eval 评估并 sort_pool 升序；随后每代执行 geqo_selection（线性偏置选 momma/daddy）、gimme_edge_table+gimme_tour（ERX，且 kid 就是 momma 的别名）、kid->worth=geqo_eval(...)、spread_chromo。spread_chromo 只拒绝严格比当前最差更差的 kid（worth 相等仍进入插入），以此维持 best→worst 有序池；循环结束后用 pool->data[0].string 作为 best_tour，再调用一次 gimme_tree 在调用者上下文重建最终 RelOptInfo，最后释放 momma/daddy、边表、池并把 join_search_private 置 NULL。

关键边界：geqo_eval 内部每次为候选创建名为 GEQO 的临时 MemoryContext，保存并在正常返回前截断 join_rel_list、把 join_rel_hash 置空后还原；join_rel_level 只用 AssertEreport 检查为 NULL，不保存/恢复（条件失败时先 Assert，再 ereport(ERROR, ERRORCODE_ASSERT_FAILED)，Assert 的具体反应依构建），然后删除临时上下文，因此评估期的 joinrel/path 在正常返回后立即失效；ERROR 路径没有正常返回的状态恢复保证，不能要求同一 PlannerInfo 继续复用。最终 gimme_tree 在调用者上下文执行，所以返回的 RelOptInfo 及其候选 Path 在 free_pool 后仍然有效。gimme_tree 不是纯左深：它用 clump 与 desirable_join（有连接子句或连接顺序限制才合并）先启发式合并，再 force 合并剩余 clump，force 只放宽启发式，仍要 make_join_rel 返回非 NULL 才合法；最终 clump 数不为 1 时报 ERRCODE_OPTIMIZER_INCONSISTENT_STATE。

对外接口：GEQO 返回的是 RelOptInfo 及其候选 Path；本文所说“最终计划”是优化器阶段结果，不等同于已经生成执行器 Plan 节点；完整 create_plan/Executor 链不在本次研究范围。

构建/可达性：geqo.h 第 30 行无条件 #define ERX，因此 geqo_main.cpp 的 #if !defined(...) 兜底不生效，PMX/CX/PX/OX1/OX2 与 geqo_mutation 虽被 Makefile/CMake 编译，但在当前源码不可达；要启用已有变体只需处理 ERX 宏（去掉/在 geqo.h 之后 undef）或调整 main 分派；main 中对应 #elif 分支已自带 alloc_chromo(kid)/free_chromo(kid) 与 city table 释放，无需改 main 代码，但需核对现有分支并重验未验证算法——仅定义 PMX 不改变分派。只有新增变体或改变所有权才需要改代码。GEQO_DEBUG 只出现在 #ifdef，本目录构建文件未定义它；但本快照不证明全构建/所有包含头未定义，调试面是否启用需以实际编译宏为准。

GUC 边界：7 个 GEQO 参数可在会话级 SET，源码只证明消费点在实际执行到的规划入口/GEQO 调用中读取；SET 是否触发后续 SQL 重新规划或使已有缓存计划失效、GUC 来源覆盖、事务局部恢复与 SHOW/pg_settings 实现均未研究，属未知边界。

范围与未运行：本结论仅来自源码静态阅读，未运行数据库、SQL、编译或故障注入；外部函数（make_join_rel、set_cheapest、have_relevant_joinclause、erand48 实现、GUC 赋值路径）只按调用契约描述，未验证其运行时实现。

- 若实际构建参数注入 -DGEQO_DEBUG，则调试打印生效；本快照只证明局部构建文件未定义
- 若存在未在本快照范围核对的其它 geqo() 调用点，门控与可达性结论需重做
- 不能把 geqo 返回的 RelOptInfo 说成已经生成的执行器 Plan
