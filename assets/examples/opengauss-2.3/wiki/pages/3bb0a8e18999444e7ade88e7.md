# 主流程：门控→遗传迭代→评估→终态重建

openGauss · content-addressed · linux-native

审阅状态 依赖已变化，待复核

主流程 flow：从 make_rel_from_joinlist 的门控到 geqo() 返回 RelOptInfo。每条 call 的 caller(symbol) 与 callee(target) 均按源码字面核对并使用真实 symbol-instance id；一个阶段有多个调用时拆成多条 call。已用 query_graph 在本地 learning run 核对 geqo_selection→geqo_copy（geqo_selection.cpp:72/73）、geqo→geqo_eval（geqo_main.cpp:191）、geqo_eval→gimme_tree（geqo_eval.cpp:93）三组 CALLS。ERX 下 kid=momma 是别名，因此“交叉”直接改写 momma->string，没有独立 kid 对象。

## 适用条件

- enable_geqo 为真且 levels_needed>=geqo_threshold
- 全部步骤在同一次查询规划调用、同一 PlannerInfo 生命周期内完成；不把 openGauss 调度模型假定为独立进程

## 边界与反例

- 若门控不成立，流程在第 1 步之后直接转 standard_join_search，不进入后续步骤
- 单独定义 PMX 不会改变分派；要改变交叉分支必须去掉/undef ERX 或调整 main 分派
