## 修复内容与证据

GCC 项目默认使用真实构建工具链及其官方插件接口，在 `-fsyntax-only` 下提取优化前函数和调用树。GNU 扩展由匹配的 GCC 解释，避免旧流程将 GCC 工程交给 Clang 时的大量部分解析。GCC 预处理器先发现真实依赖，`.map`、`.ini` 及宏选择的文件随源码冻结。Clang 路径继续可显式选择，full 模式仍由 Clang 提供。

Flex/Bison 重复或相对 `#line` 的物理位置，依据编译器活动 line-map 恢复，保留生成文件位置与原始 `.l/.y` 显示位置。真实全图中抽查五个 `core_yylex → addlit` 调用，`scan.inc` 第 16,373、16,393、16,406、16,421、16,436 行的字节偏移均指向调用括号，原始 `scan.l` 的显示位置同时保留。`geqo_selection → geqo_copy` 第 72、73 行，以及 `linear_rand` 第 56、57、69 行均为 resolved。`base_yyparse → base_yylex` 存在多定义候选，仍标为 candidate。

写入时将符号基本信息与 TU 成员关系分开追加，结束时统一生成共享符号的 contexts JSON，避免每个 TU 重写完整聚合 JSON。本次追加 2,141,920 个符号上下文成员，382,078 个符号各完成一次 JSON 汇总；交付件不携带工作用整数辅助表。TU 重试的关系所有权有索引，按具体 TU 清理。不能证明可复用的 SDK include 缓存，在昂贵的路径矩阵探测前拒绝；独立样本中探测次数从 7,884 降为 0，返回同样的“不缓存”结果。
