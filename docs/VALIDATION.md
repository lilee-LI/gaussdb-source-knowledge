## 软件回归、断网成员与积压迁移

- `python -m unittest discover -s tests` 通过 16 项。覆盖原 ECS 回放、跨文件候选、缓存命中时变更检测、缺图模块的文本定位、人工归属、成员包隔离、候选幂等、切换快照后重新核对。
- `scripts/verify_ecs_workflow.py --output <新目录>` 通过 58 个命令步骤，用两个独立工作区领取优化器与执行器的工作，各自生成基于测试夹具的提交。成员阶段主动移走协调端图文件；原图恢复后，结果可回传、重复接收、审阅和归档。验证包含候选的已发布状态、Wiki 和开发／测试／评审三种上下文读取。研究内容由脚本构造，用于检验工程协议。
- `scripts/verify_plan_scale.py --output <新目录>` 使用 220,000 项合成旧任务。保留 80 项已接受结果，暂缓 219,920 项，产生 4 张模块盘点单，指定一个问题后待办为 5。再次切换变更数为 0。
- Windows x64 从项目工作副本首次执行 `kb.cmd`，用包内 NetworkX、pypdf wheel 在私有 venv 离线安装成功。目标环境需已安装 Git 与 CPython 3.12。合成上游数据库通过 `python scripts/make_fixture.py <新SQLite文件>` 在测试时生成。

内网验收建议先对实际交付件运行 `check` 和 `start`，抽查一个已知函数的直接调用及反向调用，比较一个有覆盖和一个无覆盖模块。然后由两位成员研究一个跨模块行为，审阅后回读三种角色的证据。这样能分别定位交付格式、源码版本、研究过程和查询质量问题。
