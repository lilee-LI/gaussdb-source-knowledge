## 当前选择

以固定提交的 CodeWiki 作为第一条学习试点，使用已有 Agent 完成研究与问答；现有工程收敛为数据库方法适配、编译证据查询和效果验收。Code Comprehensor 提供方法参考，未找到可直接接入的作者完整开源实现，现有工程也没有训练 CodeContrast。

CodeWiki 是学习流水线，不将它描述成已经具备完整团队问答产品。当前用户不要求独立 Wiki/Web 门户，先复用 Agent 入口。试点结果决定是否采用该上游；不预设候选效果最优，不因新论文而重写一套平台。

首期运行范围为本地、公开 openGauss、已绑定材料、已有 Agent。没有独立模型服务不妨碍交互式试点；无人值守批量学习须另有可用执行环境，不能用模拟回执替代。

## 已查到的具体差距

- `scripts/codewiki_learning.py` 的准备阶段要求已有 baseline、预设 module_tree 等材料；专题提示还有旧试点的 `driver/fitness/population/erx/contracts` 页面名。它是有界试验适配器，不能直接称为任意模块的原生全流程。
- `scripts/unified_knowledge/evaluation.py` 要求金标 knowledge ID 已存在于发布集。它能测已入库知识是否召回，不能独立发现应学但未入库的机制。现有检查继续保留，另补从原始源码定义分母的覆盖评估。
- 当前答案语义正确性明确为待另行审阅；默认本地检索为词法基线。不能从软件测试结果推导真实问答通过。

## 知识产物与查询约束

长期内容以“模块—特性—机制”组织。每项机制有适用产品、源码版本、构建/运行条件、行为说明、必要调用或状态路径、错误与清理、源码引用、缺口和实际审阅状态；共享知识用引用复用。错误、内存、兼容、GUC 为研究视角，不机械地给每个函数生成四篇页面。

源码图保留全部已采集事实；正式知识保存所解释机制及相关路径。Wiki 是阅读输出，检索副本可重建。`compile_commands.json` 供分析工具解释代码，不作为普通问答文档；未知构建和未解析边保留不确定性。

问答先限定版本及条件，再查已有知识；缺关键依据时读取同版源码和相关关系。补读所得结论标注其核对状态，不能通过一次回答自动回写成已审正式知识。证据不足时列出缺口。

## 决策与验收

- 单独计量：范围清单是否遗漏、必要证据是否完整召回、引用是否支持结论、答案条件与边界是否正确、无依据问题是否如实处理、时间与 token 成本。
- 缺少的必要知识也计入失败；不能先把未入库问题排除，再给出高召回成绩。
- 发现宏配置混用、内存生命周期等重大机制错误时，该案例失败，修订后用开发集回归；不能反复调验收集并沿用原盲测标记。
- 比直接源码路径没有可证明的质量或效率增益，则暂停扩大量，定位知识生产、检索或回答中的具体问题。只有确认需要更好的语义匹配后才增加现成 embedding/reranker；专门训练排在其后。
- 若采用 CodeWiki 需要重写其核心规划、状态和文档流程才能完成试点，应记录不适用原因、停止该路线，基于具体失败再比较下一候选。

首个可验收交付是一个排序知识包、一个能调用知识与源码的 Agent 入口、一套原始运行/问答记录和对照报告。工程测试、源码推导、人工审阅、数据库运行分别记账；当前保持 source_only，不执行产品构建、SQL 或故障注入。
