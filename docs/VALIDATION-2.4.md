## 软件与性能验证

最终软件回归：`python -X utf8 -m unittest discover -s tests -q`，**134 项通过，165.015 秒**。全新解压目录使用包内 wheels 完成 Windows Python 3.12 离线安装；四输入建库、两个模块独立派发、stdio MCP 初始化/列工具/查询均通过。环境未安装 mcp/claude_agent_sdk/tree_sitter；无已审知识时四角色均明确返回 partial，没有伪造答案。

回归涉及四输入版本、原始行/路径映射、未编译和宏代码、全 CPP 分配、课程预算及 CAS、完整盘点前置、发布前后解释覆盖、哈希变化重开、空文件精确处置、四角色实际内容、SCC 成员与跨边、原生并发/租约/重启/过期、签名成员包/反馈及真实子代理身份。

真实 Claude 使用暴露并修复：

1. 原课程推进逐包重复解码全仓计划，首次派发等待超过 4 分钟。改为每轮只解析一次盘点就绪状态，无就绪模块直接返回；同一仓 `whole.advance` 检查实测 1.6 秒。另用 1,000 个工作包做调用边界回归，避免依赖不稳定耗时阈值。
2. 原审阅按每个 open 问题创建 gap_research，抢在功能包前面。2.4 当前课程把问题保留在经审 gap 账，按机制归并；多个 open 问题不增加同数任务，旧工作不悄悄丢弃。
3. 实现项分页原先仍评估全范围。已改为只计算本页；从 13,845 项中返回 1 项实测约 0.403 秒（含打开工作区）。
4. 非 contract 的源码消费者说明被当编译符号，阻止 source_only 知识发布。已区分文本消费者与正式 symbol bindings，并验证真实发布、依赖与知识图中不产生伪符号。
5. 关闭批次原先阻止成果回收。现在允许已提交成果，以及保留有效租约的任务在关闭后收尾并汇总；释放租约仍阻止继续读取/提交。签名验证实际原生领取/提交记录及范围。

测试通过不等于代码理解全部正确，读取回执和字段检查不等于人工专家审阅。

## 真实 Claude / GEQO 验证

使用用户已有 Claude Code 和既有模型配置，实际路由 `deepseek-v4.1-flash[1m]`。工程不会启动模型进程；外部验证工具仅用于模拟用户启动客户端，实际研究由该客户端和它的原生 Agent 执行，未把客户端/认证打入包。

目标模块为 `server/src/gausskernel/optimizer/geqo`：17 项资产、15 个 CPP、19 个物理区间。课程按实际源码调整为 3 个机制包；所有文件义务保留。研究和知识分别审阅，模式如实标 `independent_review`（另一 AI 上下文），不称人工专家。

按用户要求在可行性验证充分后停止继续深学，释放了仍在研究的本批租约，保留暂存和已审结果。本轮实际发布 **12 个知识单元：7 claim、2 mechanism、3 test_obligation**；4 个 CPP 区间有已审但带缺口的解释，15 个区间仍 open，未宣称该模块或全仓学完。

已实际导出同一修订的 Wiki、knowledge.json 和四角色查询。开发/测试/review 返回必需结构字段及来源，结果因有界裁剪仍可显示 partial；运维查询明确缺 configuration 结构字段，没有从正文或标题猜出一个配置结论。角色验收核对所需知识 ID 与实际必需字段，裁剪重复展示行不会被误认成缺少知识。不能把这轮部分知识当作四角色知识全部充分。
