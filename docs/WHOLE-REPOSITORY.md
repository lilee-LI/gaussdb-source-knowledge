# 全仓持续学习的工程合同

本功能沿用现有 snapshot/profile/run、tasks、租约、研究审阅、知识提案与知识修订。全仓计划和覆盖报告是这些记录的派生控制面，不引入另一套研究审批状态。

配置路径后，start 生成版本绑定的整仓计划、逐资产覆盖账、公共机制和跨域工作包及可领取任务。模块调查经真实审阅后提交机制候选与归并/排除依据；advance 按依赖和预算将已审反馈转成下一批任务。原始注册、语法和测试线索不会被持续调度器逐项自动排空为深度任务。

研究者通过 stage_progress 分批登记资产处置、线索处置、后续研究建议和跨模块契约核对。finish_research 将进度与正文一起绑定到当前租约及提交指纹。研究审阅接受才应用规划反馈；资产声明的知识尚未入库时，覆盖账保留 pending_knowledge，不计学完。资产的完整证据、知识内容指纹与版本适用性还需核验。

代码、头文件、SQL/语法及业务脚本声明 studied 时，需要完整引用区间的实际阅读或同版已审知识的显式复用，并指向已审知识。支持数据、生成物和排除项单列原因，不能用一次读取或目录关键词把实现直接变成已学。遗留已审知识不被全仓升级抹掉，也不因引用存在就自动推断整个模块完成。

大文件支持 partial：每个片段绑定当前租约的真实阅读及具体知识，研究通过后先记 pending_knowledge，正文入库后才累积适用引用的区间并集。完全覆盖之前仍是 partial。后续覆盖任务的身份包含已审知识进度；没有新证据的重复提交会报告 stalled，不能无限生成相同任务充数。回归预期输出属于语义材料；测试数据目录的纯数据、图片和空文件单列支持资产。

跨模块契约分别登记生产方和消费方的核对；单方结论、图的邻边与候选绑定不被视为两端验收。coverage 返回文件/模块/候选/任务/契约/使用回读各分母、阻断缺口和适用配置。签署覆盖验收只能接受同一报告指纹，不能自动批准知识或把未运行测试变成通过。

成员在模块材料包内持续完成多个任务，按原任务身份导出多个结果。同工作单接收重复包应幂等，接收新的不同任务不要求每次重新打包；相同原任务的冲突结果不得覆盖已审成果。签名同步包将协调端审阅反馈及同版参考知识送回成员，退回任务按新租约修订。

缺少跨模块材料时，协调端 `team feedback --include-asset <冻结资产ID>` 补充同快照源文件，成员sync后可继续读；不冒充已经扩展调用图。`search_source`支持对冻结范围分页字面检索，返回位置与证据ID，必须再回读才能支持提交。签名反馈对同一全局图的参考知识携带协调端新鲜度核验及内容指纹，成员不会因一跳图缺少全局邻边而错误重算参考知识适用性。

run 使用用户已有的 Claude CLI 和工程 stdio MCP，一次会话只执行一项任务。它推进已就绪工作，遇到待审、前置缺口、WIP上限或配置错误会明确停下；不代替审阅人自动接受。CLI版本、实际模型、完整过程及失败回执保存到本地，认证及模型客户端不进入发行包。

中断后 `run --resume-task <ID>` 可继续同一成员仍有效的租约，task_context提供当前草稿与覆盖指纹；到期或释放后需新租约并重新读取证据。覆盖可按模块签署或按全仓签署，报告指纹变化会使签署失效。跨模块契约即使遗漏登记，也会从已审且适用的生产/消费符号发现，单方核对不能通过。

验收与演示分别报告：全仓计划实际覆盖、所学模块、真实模型调用、软件协议回归、多人隔离工作区验证、目标GaussDB未验收范围。当前 source_only，不运行数据库、SQL、产品构建或故障注入。
